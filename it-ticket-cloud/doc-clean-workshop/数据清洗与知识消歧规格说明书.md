## 2. 物理噪音清单（破坏检索的 5 类噪音）

| # | 噪音类型 | 示例（原文） | 对检索的破坏机制 | 处置规则 |
| :--- | :--- | :--- | :--- | :--- |
| N1 | 页眉水印横幅 | `[内部绝密-严禁拍照-华科智造科技集团-202201]` | 每页重复出现，embedding 与几乎所有查询产生弱相关，**稀释真实上下文**，Top-K 被垃圾块挤占 | 整行正则剔除 |
| N2 | 页码分隔线 | `----------------- 第 2 页 共 3 页 -----------------` | 切断条款语义连续性，将第五章拆成孤立 Chunk，跨页条款无法在单次检索中完整召回 | 整行正则剔除 |
| N3 | 底稿密级横幅 | `【华科智造内部财务审计底稿·保密等级：机密】` | 高频密级词污染向量空间；且"机密封面"与业务正文同 Chunk，误导生成置信度 | 整行正则剔除 |
| N4 | 跨页表格断裂 | `[表格开始-跨页断行待处理]` … `[表格结束]`，制表符分隔数据行横跨页面且无续表表头 | 切块后模型只看到孤立数字，无法回答"该金额对应哪列语义"；拼接错位直接产生事实错误 | 缝合器统合为单张 Markdown 表，**跨页续表强制注入表头** |
| N5 | 明文敏感信息 (PII) | `13918274921` / `310104…182X` / `6222021001082736192` | 合规红线：隐私泄漏；且长纯数字串在向量库中为无意义 Token，拉低块质量 | 三类 PII 一律打码，脱敏率验收门槛 **100%** |

> 其他已纳入模式库的次级噪音：ASCII 控制字符、零宽空格、断字连字符、`-- n --` / `3 / 12` 裸页码。本批次未命中，但管道保留过滤器。

## 3. 跨文档条款冲突定位与消歧裁决

### 3.1 冲突 C1：住宿报销上限（数值 + 计费维度双重冲突）

| 维度 | 旧版（HK-2022-HR-019 第五条，2022-01-01 生效） | 新版（HK-2024-FIN-088 第二条，2024-03-01 生效） |
| :--- | :--- | :--- |
| 计费维度 | **单一上限封顶**，不区分城市 | 按城市分级（一线 / 二线 / 三线顺减 50） |
| 总监级及以上 | 600 元/天 | 一线 800 / 二线 600 / 三线 550 |
| 经理级 / 专家 (P6-P7) | 450 元/天 | 一线 550 / 二线 420 / 三线 370 |
| 普通员工 (P4-P5) | 350 元/天 | 一线 450 / 二线 350 / 三线 300 |

**冲突点**：同一职级"在北京住宿可报多少"，旧版答 600、新版答 800 —— 直接切块混合入库会让模型随机二选一，回答必错一半。

### 3.2 冲突 C2：夜间加班打车触发门槛

| 旧版第七条 | 新版第三条 |
| :--- | :--- |
| 超过 **22:30** 且公共交通停运方可报销 | 门槛提前至 **21:00（含）**，且无需特殊审批 |

### 3.3 消歧裁决规则（写入 Wiki 卡片的知识层约束）

1. **生效日期最新者胜出**：2024-03-01 起一律以 HK-2024-FIN-088 为唯一裁决依据；旧版条款整体降级为"历史废止档案"，仅在 FAQ 中保留对照，不参与正向回答。
2. **以发票日期归属版本区间**：单据日期 < 2024-03-01 → 适用旧版上限；≥ 2024-03-01 → 适用新版分级上限。审计文档 03 中"王大明多报 400 元被追回"案例即节点穿透的反面教材，作为 FAQ 佐证保留。
3. **废止关系显式登记**：新版 Wiki 卡片 `replaces: ["HK-2022-HR-019"]`，供 Day 12 结构感知切块与检索过滤使用。
4. **三线标准推导固化**：原文仅写"顺减 50 元/天"，卡片中展开为显式数值列（550/370/300），消除读者推算出错的风险。

## 4. 物理层清洗规格（`clean_pipeline.py` 实现契约）

| 阶段 | 输入 → 输出 | 规则 |
| :--- | :--- | :--- |
| 4.1 文本抽取 | `.txt/.md/.pdf/.docx` → UTF-8 文本 | txt/md 按 `utf-8-sig → utf-8 → gb18030` 探测；PDF 依赖 pdfplumber、DOCX 依赖 python-docx，**缺依赖时显式报错，不做静默回退** |
| 4.2 噪音剔除 | 原始文本 → 去噪文本 | 按 §2 模式库整行剔除，并清洗控制字符 / 零宽字符 / 断字符 |
| 4.3 表格缝合 | 断裂表格块 → Markdown 表 | 以 `[表格开始]/[表格结束]` 定界聚合，跨页空行/残留噪音视为断缝跳过，首行表头强制沿用到续表（Header Injection） |
| 4.4 PII 脱敏 | 明文 → 打码文本 | 身份证：`310104********182X`；银行卡：`622202****6192`；手机号：`139****4921`。执行顺序长号优先（身份证→银行卡→手机号），防止短号正则在长号内部误切 |
| 4.5 空白压缩 | 打码文本 → 成品 Markdown | 行尾空白剔除，连续 3+ 换行收敛为 2 |
| 4.6 报告输出 | `_clean_report.json` | 输出噪音剔除行数、缝合表格数、各类 PII 打码条数，供质量负责人对账 |

## 5. Wiki 萃取规格（`llm_wiki_synthesizer.py` 实现契约）

### 5.1 运行模式（显式选择，禁止静默降级）

- `--mode llm`：调用 OpenAI 兼容 Chat API（`OPENAI_API_KEY` / `OPENAI_BASE_URL` / `LLM_MODEL`，temperature=0.0）；缺 Key 或调用失败 → 立即报错退出，绝不以规则产物冒充 LLM 产物。
- `--mode offline`：确定性规则合成器，用于无 API 的课堂演示与 CI 回归；输出与 LLM 版同构，可逐字节复现。

### 5.2 YAML Frontmatter 规约（必填字段）

```yaml
---
id: "WIKI-{DOMAIN}-{MODULE}-{YYYYMM}"   # 全局唯一；时间戳段=effective_date 的 YYYYMM；域前缀全库统一
title: "知识卡片标题"
category: "一级分类/二级分类"             # 两级式，如 财务制度/差旅管理、内部审计/差旅复核
department: "责任部门"
effective_date: "YYYY-MM-DD"            # 裁决时效的唯一依据字段
version: "vX.X"                         # 每替代一版旧文档主版本 +1
status: "active|superseded"             # 是否已被更新版本废止；检索层按此字段过滤
replaces: ["被废止的旧文档ID或条款名称"]    # 显式声明废止的历史版本，空为 []
entities:
  - "领域实体"
  - "专有名词"
summary: "≤100 字摘要"
---
```

约束：
- **事实保真红线**：严禁修改、推断或四舍五入任何原文数值与日期；原文内部矛盾保留原值并在裁决区"数据质量说明"标注；
- 正文 §3 固定含「版本冲突特别裁决条款」引用块 + 「历史条款对比」对照表（有废止版本时必备）；
- 已被废止的旧制度卡片必须 `status: "superseded"` 并在正文裁决区写明废止方与废止日期。

### 5.3 消歧执行逻辑

1. 领域聚合：按内容把清洗语料分为 `travel`（制度组：2022 旧版 + 2024 新版）与 `audit`（审计通报组）；
2. 版本排序：按生效日期升序，**末位为现行条款**；
3. 冲突消解：现行条款进正文与标准表，旧条款进"历史旧值对照（仅备查）"与 `replaces`；
4. 表格保真：审计卡片直接引用已脱敏的缝合表，**严禁任何环节还原 PII**。
