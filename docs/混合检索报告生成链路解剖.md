# 混合检索与 Rerank 评测报告 —— 生成链路解剖

> 目的：汇报时能讲清楚「报告里每一行数字是哪个函数、哪段代码算出来的」。
> 覆盖文件：`rag_pipeline/pipelines/evaluation.py`（评测编排 + 数据采集）、
> `rag_pipeline/retrieval/hybrid.py`（检索核心）、`rag_pipeline/retrieval/reranker.py`（精排）、
> `rag_pipeline/evaluation/report.py`（报告渲染）。

---

## 一、整体数据流（全景）

```
run_evaluation()                          evaluation.py   主入口
  ├─ 装配 IndustrialHybridRetriever        hybrid.py       检索核心（四轨共用）
  ├─ 遍历 HARD_BENCHMARK_SUITE（12 题）
  │    ├─ 轨 A 纯 Dense：dense_search()
  │    ├─ 轨 B 纯 BM25：bm25_search()
  │    ├─ 轨 C RRF：rrf_fusion()
  │    └─ 轨 D 全链路：hybrid_rerank_search()
  │         └─ KspReranker.predict()       reranker.py    交叉注意力精排
  ├─ _track_metrics()                      evaluation.py  卡级指标（名次/事实命中/误召回）
  ├─ _agg()                                evaluation.py  四轨汇总（Recall/MRR/事实/误召回）
  └─ 产出 eval_records（内存中的 12 题四轨全量数据）
        │
        ▼
_generate_markdown_report()                report.py      生成「混合检索与Rerank重排评测报告.md」
_generate_retrieval_detail_report()        report.py      生成「对抗题详细召回过程.md」
```

关键点：**评测（算数字）和报告（写 Markdown）是两阶段**。`evaluation.py` 先把所有指标算好放进 `eval_records`（list of dict），`report.py` 只负责把这份数据渲染成 Markdown，本身不再做任何检索。

## 二、报告逐段解剖：每一块 ← 哪个函数

### ① 报告头部（标题 / 测试引擎 / 最优链路）

```markdown
# 混合检索与重排召回率对比评测报告
**综合最优链路**：链路 C：RRF 融合（Recall@3 100.0%, MRR 0.88）
```

- 位置：`report.py` `_generate_markdown_report()` 的大 f-string。
- **「综合最优链路」不是写死的**，由代码三级排序选出：

```python
# report.py
winner = max(stats, key=lambda t: (stats[t]["recall"], stats[t]["mrr"], stats[t]["facts"]))
```

  即先比 Recall@3，再比 MRR，最后比事实命中数，真实最优者才标 🏆。

### ② 指标口径说明

纯静态文案，硬编码在 report.py 的 f-string 里。作用是**提前防御质疑**——解释「为什么四轨不再是全 100%」：
旧口径「Top-3 拼接文本子串覆盖」会让高频通用词（时间/地址/停止）在错卡上误命中、四轨必然满分；现行口径换成卡级 Recall@3 / MRR / 限目标卡事实覆盖 / 负样本误召回。

### ③ 大盘表（四轨 Recall@3 / MRR / 事实 / 误召回 / 延迟）

- **数字来源**：`evaluation.py` 的 `_agg(track)`：

```python
def _agg(track):
    hit_n   = sum(1 for r in positives if r[f"{track}_rank"])          # 卡级命中数
    mrr     = sum(1.0 / r[f"{track}_rank"] for r in positives ...) / n_pos
    facts   = sum(r[f"{track}_hits"] for r in positives)               # 事实覆盖
    false_n = sum(1 for r in negatives if r[f"{track}_false"])         # 负样本误召回
```

- **渲染**：`report.py` 的 `crown()`（加 🏆）、`mrr_s()`、`fact_s()`、`false_s()`、`lat()`，读 `_agg` 算好的 `stats`。
- **延迟列**：从每题实测 `r["dense_time"]` 等求平均（evaluation.py 尾部），不是模板写死的假值。

### ④ 每题明细（命中率 + Top-3 命中）

```markdown
### [HC-01] 系统修复命令硬匹配（hard）
- **纯 Dense 向量检索命中率**：0/2（❌ 未命中，目标卡未召回）（118.3ms）
  > Dense Top-3 命中：
  > 1. [ITKB-APPENDIX-3#c1]，分 0.4227 ...
```

- **`0/2` 的分子分母**：来自 `_track_metrics()`：

```python
# evaluation.py
hits = sum(1 for f in expected if f in tgt_text)   # 事实只在「召回的目标卡」正文里计数
rank = (ids.index(target_id) + 1) if target_id in ids else None
```

  分子 `hits` = 黄金考点命中数，分母 `expected_count` = 该题考点总数。
  ⚠️ **`0/2` 的 2 是「考点数」，不是「候选数」**——和下面 Top-3 的 3 条候选是两码事。

- **渲染**：`report.py` 的 `_verdict()`（✅/⚠️/❌）、`_rk()`（名次）、`_top3()`（候选列表）。
- **Top-3 候选数据**：来自 `evaluation.py` 的 `_snips()`，直接读 `dense_raw` / `bm25_raw` / `fused` / `full_docs` 这些**未去重的候选**，每条带「序号 + id + 分数 + 截断正文」。

### ⑤ 四轨检索本身（报告数字的源头）

| 报告里的轨 | 调用函数（hybrid.py） | 核心公式 |
|---|---|---|
| 纯 Dense | `dense_search()` | Chroma 余弦相似度 |
| 纯 BM25 | `bm25_search()` | `rank_bm25` 关键词打分 |
| RRF 融合 | `rrf_fusion()` | `Σ 1/(k + 名次)`，k=60 |
| 全链路 | `hybrid_rerank_search()` | 召回 → RRF → Rerank → `0.6/(10+RRF名次) + 0.4/(10+Rerank名次)` |

`hybrid_rerank_search` 内部两个关键子函数：

- **`_ranks_of(scores)`**：把 Rerank 绝对分转成「名次」（同分并列取名次相同）。原因是 Rerank 绝对分会漂移、跨查询不可比，只有名次是稳定信号。
- **共振保护块**（`_top_parent_ids()`）：BM25 与 Dense 各自前 2 名的父块交集，不允许被 Rerank 单点踢出 Top-3。报告里带 🛡 标记的候选就是它救回来的。

### ⑥ 报告尾部总结（三、核心架构总结）

`report.py` 的静态文案 + `concl3` 变量（根据 winner 是 C 还是 D 动态选文案）——所以「RRF 领先」和「全链路领先」两套结论文案是自动切换的，不用手改。

## 四、关键公式速查

| 名称 | 公式 | 参数 |
|---|---|---|
| BM25 分 | 经典 Okapi BM25 | 语料 IDF + 词频 |
| Dense 分 | 余弦相似度 | qwen3-embedding-8b（4096 维） |
| RRF 分 | `Σ 1/(k + rank)` | k = 60（`rrf_k`） |
| Rerank 分 | Cross-Encoder 相关度 | qwen3-reranker-8b（/rerank 端点） |
| 融合分 | `rrf_weight/(fuse_k + RRF名次) + rerank_weight/(fuse_k + Rerank名次)` | rrf_weight=0.6，rerank_weight=0.4，fuse_k=10 |
| MRR | `Σ 1/名次 / 题数`（目标卡名次倒数均值） | — |

> 补充：RRF 分、融合分都是「名次分数」，绝对大小无意义（RRF 约 0.016、融合分约 0.09），
> 只用于比较相对排序。真正的相关度是 Dense 的余弦分（0~1）和 Rerank 的交叉注意力分（0.17~0.42）。
