# 已提交工单重新编辑

**目标：** 用户在“我的工单”详情点击“重新编辑”，回到原提单表单修改自己的内容；问题性质和分类不可修改；保存不改变工单状态和计时；详情和列表显示问题类型。

**方案：** 复用 EmployeeView 的表单和校验，新增编辑模式以及 PUT /api/v1/tickets/{id}。后端用独立 DTO 和字段白名单更新内容，在事务内验证归属、锁定工单、同步附件并记录 TICKET_EDIT。不调用创建、状态机、SLA 或自动路由。所有已提交的本人工单均可编辑，保留当前生命周期状态。

**约束：** 保留工作区已有改动；不新增依赖或数据库字段。分类显示优先使用提交时的 category_snapshot，停用的分类仍可读。已有照片的删除延迟至保存事务。编辑期间暂停新建草稿自动保存，结束编辑恢复原新建表单。

## 实现与验证记录

- 保留 ticket.updated_at 原值，显式覆盖数据库 ON UPDATE 行为，因为现有自动验收、待补充、外部等待任务用此字段起算。修改时间记录于 TICKET_EDIT 流水。
- 重传已有照片时按 hash 复用或恢复原照片，避免已撤回照片仍占用唯一键而导致保存失败。
- 新建草稿中已使用的照片若被编辑上传接口去重返回，提示改选照片，避免绑定或撤回新建草稿附件。实际上传请求计数和编辑代次防止迟到响应写入其他表单。
- 工单服务：97 项测试通过，其中 TicketEditTest 15 项。
- 前端：employee-ui 和 ticket-editing 共 16 项测试通过；浏览器使用模拟 API 验证真实 Vue/Element Plus 页面，包括原分类停用、回填、锁定、取消、保存失败后重试、上传新照片后删除。
- 前端全量测试另有 20 项既有失败（账号、旧草稿、SLA 契约），在临时基线目录恢复本次修改前的 EmployeeView/api 后得到相同失败集合，本次没有新增失败。
- Vite 构建通过；保留已有大 chunk 提示。用户随后要求重启，已重新打包并启动 ticket-service；确认数据库连接、Nacos 注册正常，新运行包包含 PUT 编辑接口。前端 HTTP 200，后端未认证请求返回预期的 401。
