# 人工咨询聊天附件

目标：会话发起人与当前工程师均可将图片或文件拖入输入区自动上传，或通过回形针按钮选择文件；上传后预览，点击发送共享附件，支持仅附件消息。

实现：复用现有附件表和会话消息元数据，不新增数据库结构。上传草稿按本人及会话隔离，发送时事务绑定至消息，下载仍受会话参与者权限控制。两端复用上传与消息附件组件，延续当前主题。单文件20MB、单条消息最多10个附件。AI阶段不识别附件，本次入口用于人工沟通。

- [x] 后端：上传/草稿撤回/受权下载；消息引用验证及持久化；回归测试。
- [x] 前端：拖放、附件按钮、进度、重试、移除；图片预览与文件下载。
- [x] 集成：员工与工程师两端、附件-only、状态禁用、切换会话防串消息。
- [x] 验证：前后端测试/构建、实际两账号互发图片与文件、刷新恢复、下载权限。

验证记录：后端220项通过（含38项附件测试），前端附件及相关咨询回归79项通过，前后端构建成功。真实浏览器验证工程师选择TXT附件作为首条回复、员工拖入PNG并附文字、工程师预览图片后拖入CSV、员工下载字节与文件名一致、刷新恢复、管理员作为非参与者下载404。修复Escape关闭图片时连带退出聊天抽屉的问题，以及重复发送确认/同数量新消息漏刷新问题。同会话的草稿删除等待跨上传组件实例共享，避免移除后切换会话再重传导致附件失效；终态可清理本人未发送草稿。测试创建的会话均已结束，既有用户会话未关闭。

接口：`POST /consultations/{sessionId}/attachments`；`DELETE /consultations/{sessionId}/attachments/{attachmentId}`；`GET /consultations/{sessionId}/attachments/{attachmentId}/content`；已有消息接口增加 `attachment_ids`，消息投影增加 `attachments`。

用户约束：不读取任何模型 Key 配置；启动服务仅通过现有配置机制加载，日志输出不包含凭据。
