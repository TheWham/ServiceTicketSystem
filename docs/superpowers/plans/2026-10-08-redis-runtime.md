# Redis 本地服务完善

**目标：** 将当前仅有客户端配置的 Redis 缓存落地为可启动、停止、检查和重启恢复的本地服务，并验证知识服务使用真实 Redis。

**部署设计：** 本机没有可用 Docker Desktop，采用项目 `.devtools` 便携工具方式运行 Redis Windows 社区构建 8.2.9（仅本地开发）。安装包固定下载地址及 SHA-256；监听 127.0.0.1:6379、开启 protected-mode，256MB 上限、allkeys-lru，AOF everysec。持久化数据和日志留在忽略目录。不改已有模型凭据或远程业务数据。

**交付：**

- [x] 增加安装/启动、停止、状态检查脚本与配置；重复启动不产生重复进程，端口被他人占用时明确失败。
- [x] 增加当前用户登录自动启动入口，可通过停止脚本移除。
- [x] Compose 增加官方 Linux Redis 镜像、持久卷、健康检查和 restart 策略，供 Docker 环境使用。
- [x] 增加可选真实 Redis 客户端集成测试，验证写入/命中/TTL/环境隔离，不依赖知识正文或修改业务反馈。
- [x] 实测 PING、读写、过期、优雅停止重启后的恢复，以及 Spring 客户端读写；更新运行文档。

**缓存语义：** Redis 是可重建的缓存，MySQL 仍是知识审核事实来源；既有 Redis 故障降级逻辑保留。默认本地监听无需密码，外部环境使用 REDIS_PASSWORD 配置认证。

**验证记录：**

- 安装前真实 Spring Redis 测试因连接失败而失败，安装后相同测试通过；连同既有消费测试共 9 项通过。
- 本机 `127.0.0.1:6379` 返回 PONG，内存上限 256MB、allkeys-lru、AOF 状态正常；知识服务健康接口为 UP。
- 写入独立短期测试键后优雅停止再启动，值恢复；测试键已删除。
- 独立审查发现多端口共用持久化目录问题，已按端口隔离数据目录和自动启动入口；实测 6379/6380 的值和目录隔离，临时 6380 实例已停止。
- 外部测试进程占用 6391 时，启动/停止脚本均拒绝操作且未影响该进程。
- 当前用户登录启动项已创建。Docker YAML 已解析、官方镜像标签已校验存在；本机无可用 Docker 引擎，未运行 Compose 容器。
