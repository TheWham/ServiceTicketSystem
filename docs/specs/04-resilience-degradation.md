# 容错、防御与降级契约

| 项目 | 约束 |
|---|---|
| 规范编号 | RD |
| 技术基线 | Java 17、Spring Boot 3.x、MyBatis/MyBatis-Plus、MySQL 8.x；Redis 仅作排队、序列和缓存 |
| 权威范围 | 超时、重试、幂等、并发防御、熔断、降级、补偿、死信、监控和灾备 |
| 正常契约 | 数据类型见 `DM-*`，AI JSON 见 `AI-*`，合法业务迁移见 `SM-*` |

本规范不重复正常字段、JSON Schema 或状态矩阵。它只定义发生故障、超时、重复请求、并发冲突或依赖不可用时系统必须如何防御和恢复。

## RD-001 故障分类

| 类别 | 示例 | 处理原则 |
|---|---|---|
| 客户端可重试 | 网络断开、连接重置 | 保留幂等键，客户端可安全重试。 |
| 服务端瞬时故障 | 5xx、数据库连接池暂满 | 有界重试，超过上限进入补偿。 |
| 外部依赖故障 | SSO、HR、CMDB、邮件、对象存储、模型、RAG 索引 | 隔离依赖，不阻塞可用主流程。 |
| 业务冲突 | 乐观锁失败、责任人改变、非法状态 | 不盲目重试，重新读取并返回明确错误。 |
| 数据安全故障 | 恶意附件、越权、敏感泄露风险 | 立即拒绝、审计并告警。 |

## RD-002 幂等契约

以下操作必须支持幂等：创建咨询、转人工、创建工单、保存补充、状态动作、发送通知、知识发布、RAG 索引刷新。

- 幂等键由 `Idempotency-Key` 或事件唯一 ID 提供，最长 128 字符。
- 服务端保存主体、操作、请求摘要、结果和过期时间；相同键与相同摘要返回原结果。
- 相同键但请求摘要不同返回 `IDEMPOTENCY_CONFLICT`，不得执行新操作。
- 工单创建幂等记录与主记录、首条流转、首个 SLA 在同一事务内写入。
- 通知幂等键为 `eventId:receiverId:channel`，只允许一个成功发送结果。
- 消息发送不允许用重试覆盖正文；每次客户端重发必须携带消息客户端 ID。

## RD-003 超时和重试策略

| 依赖/操作 | 超时 | 重试 | 失败后的动作 |
|---|---:|---:|---|
| SSO/HR 同步 | 10 秒 | 3 次，指数退避 | 保留最近有效组织数据，管理员告警。 |
| CMDB 校验 | 2 秒 | 1 次 | 标记资产待核对，不阻塞提单。 |
| 站内通知 | 3 秒 | 3 次 | 写通知失败记录，进入补偿队列。 |
| 企业邮箱 | 10 秒 | 3 次，指数退避 | 进入死信并通知管理员。 |
| 对象存储上传 | 30 秒 | 2 次 | 附件标记失败，可删除或重传；不污染工单正文。 |
| AI/RAG 请求 | 首段 5 秒、完整 15 秒 | 同一请求最多 1 次 | 返回拒答或 AI 不可用，保留转人工/提单入口。 |
| 状态写入 | 事务超时 | 不自动重放业务动作 | 重新读取版本，返回并发冲突。 |

重试只用于确认可安全重试的瞬时故障；不得对业务拒绝、鉴权失败、文件安全失败和非法状态进行重试。

客户端重试上限：同一写请求最多由客户端重发 3 次，间隔采用 100ms、500ms、1500ms 抖动退避；每次必须复用原 `Idempotency-Key`。服务端已返回业务结果后，客户端不得用新键重放同一业务动作。

## RD-004 SLA 计时防御

- 响应 SLA 和完成 SLA 使用服务日历计算，不能使用客户端时间。
- 客户端断网、刷新和重复提交不得暂停或重置 SLA。
- 只有 `SM-TICKET-003` 定义的合法等待状态可以暂停完成 SLA。
- 定时任务必须使用 MySQL 抢占表/租约或带版本条件的更新，确保同一超时事件只处理一次；Redis 不作为业务事实锁。
- 80% 目标耗时发送临近超时提醒；响应 SLA 在第 8 个工作分钟提醒；提醒失败不改变 SLA 结果。
- 到期任务必须写入 `SLA_BREACHED` 领域事实事件；补偿任务重复消费不得重复通知或重复转派。

## RD-005 自动分配和转派防御

- 分配前必须读取最新团队成员状态、负载和分类路由版本。
- 使用乐观锁或短时租约防止两个分配器把同一任务同时分给不同工程师。
- 自动响应超时每位候选人最多尝试一次；候选人耗尽进入异常队列，不无限循环。
- 工程师主动转派达到 3 次进入异常队列；转派不得重置响应或完成 SLA。
- 无候选人时工单保持 `NEW` 并进入异常队列；不得分配给无关分类团队。
- 平台管理员处理异常队列时必须填写原因，重复点击管理员动作必须幂等。

## RD-006 依赖降级

| 依赖 | 降级行为 | 不得发生 |
|---|---|---|
| SSO 暂时不可用 | 已有有效会话按会话策略继续；新登录提示稍后重试 | 不绕过身份校验。 |
| HR 同步失败 | 使用最近成功快照，标记同步过期 | 不覆盖有效组织数据。 |
| CMDB 不可用 | 工单标记资产待核对 | 不阻塞提交。 |
| 邮件不可用 | 保留站内通知和待办，记录邮件失败 | 不阻塞状态迁移。 |
| 对象存储不可用 | 允许保存无附件工单；附件可重传 | 不伪造成功 URL。 |
| RAG/模型不可用 | 返回 AI_UNAVAILABLE/拒答，提供转人工和直接提单 | 不伪造模型成功、检索命中或知识引用。正常空检索不是故障，按 AI-001 允许办公 IT 通用回答。 |
| RAG 索引滞后 | 使用最后一个已知有效索引并标注版本 | 不检索已下线版本。 |
| 知识发布事件失败 | 保持知识发布事务结果，索引进入补偿队列 | 不把未索引内容伪装为已可检索。 |

| AI 评测未达上线门槛 | 关闭 AI 综合回答，仅保留知识搜索、人工咨询和直接提单 | 不展示未通过评测的生成回答。 |
| AI 首段/完整回答超时 | 返回 `AI_UNAVAILABLE` 或结构化拒答，显示转人工和提单入口 | 不阻塞咨询转人工或工单提交。 |
| 附件扫描超时/失败 | 附件保持不可用并允许重传；无附件字段的主业务继续 | 不生成可下载但未扫描的 URL。 |

## RD-007 断路器与隔离

- AI、邮件、CMDB、对象存储和索引服务分别设置连接池、线程池和断路器，不共享无限队列。
- 断路器打开时快速返回定义好的降级结果，半开探测成功后逐步恢复。
- 外部依赖响应不得占用工单主事务连接。
- 用户请求、异步消费者和定时任务使用独立并发隔离，避免通知或索引积压拖垮提单。
- 断路器默认采用连续 5 次失败打开、30 秒后半开、连续 3 次成功关闭；具体实现可替换但必须保留相同的状态语义和监控指标。
- AI/RAG、邮件、CMDB、对象存储和 HR 同步各自设置最大并发和队列长度；队列满时立即返回对应降级结果，不等待无限排队。

## RD-008 死信、补偿和人工介入

- 通知、索引、邮件、HR 同步和知识发布事件超过重试上限进入死信队列。
- 死信必须保存事件 ID、首次失败时间、最后错误、重试次数和关联对象。
- 平台管理员可查看、重放或标记已处理；重放必须复用原事件 ID并保持幂等。
- 重放失败继续保留原死信，不创建无限新事件。
- 主业务已成功而异步副作用失败时，界面展示“处理中/待补偿”，不得回滚已完成的用户业务动作。
- 死信重放前必须再次执行当前权限校验；原操作者已离职或权限被收回时只能由平台管理员处理。

## RD-009 安全防御

- 所有对象读取先执行服务端角色、对象归属和当前责任校验。
- 上传校验真实 MIME、文件大小、扩展名、哈希和恶意扫描；扫描超时按失败处理。
- 附件下载使用短期授权地址，地址泄露不应永久可用。
- 速率限制应用于登录、AI 消息、文件上传、验证码和管理员接口。
- 管理员查看撤回原文、修改优先级、异常关闭、重新打开、知识发布等操作必须二次确认并审计。
- 发现越权或恶意输入时立即拒绝并告警，不进入普通重试流程。

## RD-010 可观测性与告警

每个请求、事件、任务和外部调用必须携带 `requestId/traceId`，并记录耗时、结果和错误分类。至少监控：

- 95% 页面/API/AI 延迟；
- 响应和完成 SLA 临近超时、违约；
- 自动分配失败、连续转派和异常队列积压；
- 通知成功率、邮件死信、索引延迟和 AI 拒答率；
- 附件扫描失败、越权拒绝和高危安全告警；
- 数据库连接池、消息积压和断路器状态。

告警必须区分通知级别、关联对象、首次发生时间、当前状态和处理链接；告警重复发送使用告警指纹幂等。

## RD-011 灾备与恢复

- 数据库、对象存储和关键配置持续备份，目标 `RPO <= 15 分钟`、`RTO <= 2 小时`。
- 恢复后先校验主数据、状态、SLA、幂等记录和审计链，再开放写入。
- 异步事件使用可重放日志或死信恢复，不依赖客户端重新提交。
- 每半年执行一次完整恢复演练，验证工单、附件、知识版本、索引版本和审计可读性。
- 演练报告记录恢复时间、丢失数据范围、失败项和整改负责人。

## RD-012 容错验收

- 重复提交只创建一个工单、首条流转和 SLA。
- 数据库锁冲突不会产生双重状态迁移。
- 工程师响应超时只发生一次有效自动转派。
- 通知失败不阻塞主业务，达到上限进入死信并可幂等重放。
- AI 超时或不可用时不伪造成功回答；正常空检索可产生经 AI-001 校验的办公 IT 通用回答，转人工和直接提单仍可用。
- CMDB、邮件、对象存储、HR 同步任一失败时，其他主流程仍按本规范降级。
- 恢复演练达到 RPO/RTO，且状态、审计、附件和知识索引一致。

## RD-013 主链路不可阻断保证

- AI、RAG、邮件、CMDB、对象存储、知识索引和 HR 同步均属于外部依赖；任一依赖失败不得阻止员工提交无该依赖要求的工单，也不得阻止人工咨询转接。
- 主事务只负责身份/权限校验、字段校验、状态迁移、流转记录、SLA 投影和 `OutboxEvent`；外部调用不得持有主事务数据库连接。
- 降级响应必须可观测：记录依赖名、断路器状态、超时/错误分类、是否使用 fallback、请求追踪 ID 和关联对象 ID；不得记录令牌、完整聊天正文或敏感附件内容。
- 所有降级结果必须是显式可判定的有限集合（例如 `AI_UNAVAILABLE`、资产待核对、通知待补偿），禁止用空成功响应掩盖失败。

## RD-014 Redis 防御与恢复

- Redis 队列只接收已在 MySQL 提交成功的 `OutboxEvent`；发布失败时由 MySQL 扫描补发，不允许先写 Redis 再写主表。
- 队列消息使用 `eventId` 作为消费幂等键；消费确认前不删除，重试超过上限转入 Redis 死信队列并在 MySQL 记录 `DEAD_LETTER` 状态。
- Redis 序列仅用于分配候选号段；应用重启、Redis 清空或主从切换后必须允许跳号，并通过 MySQL 唯一键检测碰撞后重试，不得回退序列。
- Redis 缓存采用 cache-aside：先读缓存，miss 时读 MySQL，再按短 TTL 写回；MySQL 写事务提交后发送失效事件。缓存读失败不影响主流程，缓存写失败只记录指标。
- Redis 不可用时：异步任务回退到 MySQL Outbox 扫描，序列回退到 MySQL 号段/唯一键重试，查询回源 MySQL；不得把 Redis 异常返回为业务成功。
- Redis key 必须包含环境、租户边界（本系统为单企业）、对象类型和对象 ID，并设置 TTL/最大长度；禁止缓存聊天原文、撤回原文、令牌和敏感附件内容。
