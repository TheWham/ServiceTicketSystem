# IT 服务工单系统 —— 技术风险登记册

| 风险编号 | 风险源与触发条件 (Trigger) | 潜在危害等级 | 预防方案 (Mitigation) | 运行时降级/兜底预案 (Fallback) |
| :--- | :--- | :--- | :--- | :--- |
| **TR-01** | **相似推荐接口超时或异常**。提单页 category 选中 300ms 防抖后调 `POST /api/kb/recommend`，该接口依赖检索 + 大模型摘要，是全系统唯一不稳定链路。 | **高** | 接口异步非阻塞，与提单主流程物理隔离；超时阈值定为 2s，到点即熔断。 | 超时或异常时前端静默隐藏推荐卡，不弹错误框、不阻塞提单；搜索词与资产号异步入 MQ 留作语料，保证提单 100% 可用。 |
| **TR-02** | **知识库覆盖不足导致模型编造**。FAQ 冷启动期命中少，模型可能脱离语料发散猜测解决方案。 | **高** | 检索设相似度硬阈值，低于阈值直接拦截；输出走 JSON Schema 强约束，推荐结果必须引用 KB 条目编号，禁止无依据生成。 | 无命中返回 `has_recommendation=false`，前端整卡不渲染——宁可不推荐，也不输出猜测内容。 |
| **TR-03** | **通知重复推送**。8 类状态事件 × 多接收人，状态抖动或接口重试会让同一员工被反复打扰。 | **中** | `notify_dedup_key`（`{ticket_id}:{event_type}`）建唯一索引，同事件 1 分钟内防重；推送侧加 Redis 锁（TTL 60s）。 | 投递状态落库可查；失败按策略重试，重试仍失败支持人工补发。 |
| **TR-04** | **企微通道故障导致高优工单通知漏达**。推送超过 3s 判定超时，HIGH 工单延误会扩大故障影响面。 | **高** | 通道调用与业务解耦，单独设 3s 超时；按优先级分级配置通知通道。 | HIGH 工单失败自动加发短信兜底；MEDIUM/LOW 仅重试不发短信，避免短信成本失控。 |
| **TR-05** | **高危写操作误触发或越权**。改派、关闭、驳回及后续自动派单，一旦误调直接影响工单归属与责任认定。 | **极高** | 所有写操作强制走状态机白名单校验，非法流转直接拒绝；自动派单强制 Human-in-the-Loop，主管点击确认后才生效。 | 写接口幂等设计 + 失败补偿；全量流转日志逐单可回溯，异常流转实时告警主管。 |
| **TR-06** | **SLA 超时升级不生效**。`TIMEOUT_ALERT` 规则已在 PRD 定义，但定时器尚未挂载，超时工单可能无人察觉。 | **高** | 定时任务注册纳入上线检查清单，发布时逐条核对签收。 | 定时器挂载前，由主管用列表页（支持按状态、发起时间检索）人工筛查停留超时工单过渡。 |
| **TR-07** | **FAQ 归档脱敏不彻底**。已关闭工单含员工姓名、工号、资产编号、内网 IP，直接入库即构成信息泄露。 | **高** | 归档前强制过脱敏流水线，上述四类敏感信息必检；按「现象/排查/方案」三段式切分，不做定长机械切分。 | 文章上架前人工抽检；发现泄露立即下架，并回溯同源语料批量清理。 |
| **TR-08** | **高峰期检索与模型 API 限流、成本失控**。如月初集中报障，QPS 突增触发 429 或产生高昂调用费。 | **中** | 相似问题挂语义缓存直接命中返回；全局接口限流；前端 300ms 防抖从源头压住无效调用。 | 触发熔断时推荐功能整体静默降级，提单与通知主流程不受影响。 |
