### 📦 3 个专项 Demo 的设计与落地成果

#### 1. PDF 文件专项治理 Demo

- **目录位置**：[`day11/demos/01_pdf_governance/`](file:///Users/lucas/Documents/项目/武汉柯莱特企培/day11/demos/01_pdf_governance)
- **运行命令**：`python3 run_demo.py`
- **核心工程实现**：
  1. **页面类型智能判别**：依据页内字符量与图像元数据，自动判定当前页是 `VECTOR_TEXT`（原生矢量文字）还是 `SCANNED_IMAGE`（图片扫描件）；
  2. **矢量页治理**：使用 `pdfplumber.find_tables()` 提取表格并转为 Markdown 结构，结合 `PyMuPDF` 过滤表格区域，提取上下文自包含的正文段落，避免表格数字被按行割裂；
  3. **扫描件治理**：演示灰度化与二值化图像预处理，并挂接 **Post-OCR 规则纠错流水线**，将 `10O,00O.OO` 修复为 `100,000.00`、`人氏币` 修复为 `人民币`、`6222 O2IO` 修复为纯数字账号，杜绝下游程序 `ValueError` 崩溃。

---

#### 2. Word (`.docx`) 文件专项治理 Demo

- **目录位置**：[`day11/demos/02_docx_governance/`](file:///Users/lucas/Documents/项目/武汉柯莱特企培/day11/demos/02_docx_governance)
- **运行命令**：`python3 run_demo.py`
- **核心工程实现**：
  - **策略 A 缺陷暴露（传统方式）**：分别遍历 `doc.paragraphs` 和 `doc.tables`，导致表格全部坠落到文档最末尾，前置业务前提与后继声明彻底割裂；
  - **策略 B 架构解法（推荐流式）**：遍历 `doc.element.body` 的底层 XML 节点（`<w:p>` 与 `<w:tbl>`），严格按照**物理阅读流交替提取**，实现标题、说明段落、结构化 Markdown 表格与后继声明的严格保序。

---

#### 3. Excel (`.xlsx`) 文件专项治理 Demo

- **目录位置**：[`day11/demos/03_excel_governance/`](file:///Users/lucas/Documents/项目/武汉柯莱特企培/day11/demos/03_excel_governance)
- **运行命令**：`python3 run_demo.py`
- **核心工程实现（双轨制策略）**：
  - **策略 A（纯明细表 ➔ Text2SQL）**：将上百行流水数据导入 SQLite 关系引擎，演示自然语言问题（如“华东大区政企客户销售总额与毛利”、“Q3 各大区已回款均值”）转化为确定性 SQL 聚合，**杜绝大模型进行切块心算而引发的算术幻觉**；
  - **策略 B（业务规则表 ➔ 行级自包含切片）**：将职级差旅报销矩阵逐行重构，每一行显式绑定全部表头字段属性，输出为自包含的 Markdown 块与 JSON 元数据，确保任意单行被向量库独立召回时均具备完整语境。
