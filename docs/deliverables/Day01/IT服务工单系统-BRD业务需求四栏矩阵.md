# IT 服务工单系统——BRD 业务需求规划四栏矩阵实操表

**【小组选题名称】**：企业内部 IT 服务工单系统——从即时求助到服务闭环

**【小组成员与角色】**：工程负责人（待填写） / 方案负责人（待填写） / 质量验收人（待填写）

> 文档说明：本文按照所提供图片的四栏模板编写。企业实际规模、历史数据、预算和成员姓名尚未提供；下文现状为待调研验证的典型情况，数值为规划目标或测算假设，不代表已取得的经营成果。

## 一、场景定义与业务目标

企业内部员工遇到电脑故障、软件安装、账号权限、网络问题、系统报错等 IT 问题时，通过统一入口提交工单，由 IT 团队按优先级派单处理、闭环追踪，并对服务质量和 IT 效能进行数据化管理。

**一句话定位**：把“微信喊人修电脑”变成“可追踪、可衡量、可复盘的 IT 服务流程”。

**业务目标**：统一服务入口、明确责任归属、保障紧急问题及时响应、规范权限与软件申请、沉淀解决经验，并用可核验的数据衡量服务质量。

**业务流程**：员工提交 → 分类与优先级判定 → 按需审批 → 派单与受理 → 处理与协同 → 员工确认 → 关闭评价 → 知识沉淀与运营复盘。

**核心决策角色**：IT 负责人作为业务牵头人和预算提案人；预算审批由企业授权管理层负责；业务主管、系统负责人或数据负责人按申请类型审批；信息安全人员参与高风险事项审核。

## 三、关键业务规则与验收口径

### 3.1 工单必备信息

- 提交信息：工单编号、申请人、部门、联系方式、问题类别、问题描述、发生时间、影响范围，以及适用时的设备或系统、截图附件。
- 流转信息：优先级、负责人、状态、提交与受理时间、响应时间、审批记录、转派记录、暂停原因与起止时间、解决与关闭时间。
- 结单信息：处理过程、解决方案、实际人工工时、解决确认方式、评价、重开记录、关联知识或重大故障。
- 采集原则：按业务需要收集，密码、验证码等身份凭证不得作为工单内容；日志和截图涉及敏感信息时先脱敏。

### 3.2 优先级与服务时限

以下为讨论用目标，须由 IT 与业务部门根据值班资源确认后启用。响应指人工有效受理并告知处理安排，自动回执不算响应；恢复或解决时限不等同于工程师实际人工工时。

| 优先级 | 典型判断条件 | 首次响应目标 | 恢复或解决目标 | 计时范围 |
| :--- | :--- | :--- | :--- | :--- |
| P1 紧急 | 关键业务整体中断，大范围用户受影响，无可行替代方案 | 15 分钟内 | 4 小时内恢复关键业务或提供有效替代方案，后续根因整改另行跟踪 | 如企业具备值班保障，按 7×24 小时计时 |
| P2 高 | 部门级业务严重受阻，影响多人，替代方案有限 | 1 个服务小时内 | 8 个服务小时内恢复或解决 | 按公布的服务日历计时 |
| P3 普通 | 单人设备或一般软件故障，影响局部工作 | 4 个服务小时内 | 16 个服务小时内解决 | 按公布的服务日历计时 |
| P4 计划 | 常规软件安装、咨询或非紧急权限申请 | 8 个服务小时内 | 完整申请且审批通过后 24 个服务小时内完成执行 | 审批周期单独统计，申请总历时同时展示 |

- 优先级由影响范围与紧急程度共同确定，员工可说明紧急原因，最终按规则判定；人工修改须留痕。
- “服务小时”指企业服务日历内的有效小时；如每日服务 8 小时，16 个服务小时相当于 2 个服务日。
- 等待员工补充资料等允许暂停的情形需提前定义；暂停不影响总历时的展示，内部排队或无人接单不得用暂停掩盖。
- P1 的恢复目标、值班覆盖和升级联系人须同步落实，否则不得直接承诺对应时限。

### 3.3 状态与关闭规则

- 基本状态：待受理、待审批、待分派、处理中、待补充、待确认、已关闭、已取消；按场景允许跳过审批。
- 工程师提交解决方案后进入待确认，员工确认恢复后关闭；员工反馈未解决则退回处理。
- 建议待确认 3 个服务日后提醒，5 个服务日仍无反馈时可按已告知的规则自动关闭，明确标注“超期自动关闭”，不计为员工主动确认或满意。
- 建议关闭后 7 个自然日内同一问题可重开原单；超过期限建立关联新单。统计保留原始时间和重开次数，避免通过反复结单美化时效。
- 账号权限和软件申请须满足必要审批与执行记录要求；自动关闭不能绕过这些要求。

### 3.4 指标定义与验收方式

| 指标 | 统计口径 | 建议验收目标或方式 |
| :--- | :--- | :--- |
| 信息采集、派单与催办用时 | 按环节记录或抽样观察实际 IT 人工投入，不用状态停留时间代替 | 同类工单在试点前后分别抽样，核验四栏矩阵中的时间改善目标 |
| 首次响应时长 | 提交至首次人工有效响应的服务时间 | 按优先级统计中位数与第 90 百分位，检查是否满足对应目标 |
| SLA 达标率 | 统计期内到期的考核事项中，按期完成的事项数占比；到期仍未完成计未达标 | 响应和恢复或解决分别统计，整体规划目标均不低于 95% |
| 错派率 | 因类别或技能匹配错误发生改派的工单数 ÷ 已派单工单数 | 不高于 5%；正常升级、轮班交接不视为错派 |
| 满意率 | 有效评价中 4 分及 5 分评价数 ÷ 有效评价总数，采用 5 分制 | 不低于 90%；同时披露评价响应率，不将未评价视为满意 |
| 必要审批留痕完整率 | 具有完整必要审批记录的已执行申请数 ÷ 需要审批的已执行申请数 | 100%；抽查审批人、时间、结论及执行内容是否一致 |
| 结单记录完整率 | 具有必备处理与结单信息的关闭工单数 ÷ 关闭工单总数 | 100%；自动关闭与员工确认关闭分别标识 |
| 重开率 | 某批关闭工单在关闭后 7 个自然日内重开的数量 ÷ 该批关闭工单总量 | 等观察窗口结束后统计；先建立基线，再确定改善目标 |

试点建议选取 1—2 个部门，覆盖报障、权限审批、转派、超时、重开和差评回访场景；先采集现状基线，再连续观察上线后至少 4 周的数据。功能验收应包含正常路径和异常路径，效果验收应披露样本量、工单结构与人员变化。

## 四、经济效益测算

### 4.1 测算假设

| 参数 | 示例取值 | 说明 |
| :--- | :--- | :--- |
| 年度工单量 | 12,000 单 | 假设平均每月 1,000 单，待实际台账验证 |
| IT 综合人力成本 | 100 元/小时 | 仅用于释放产能的金额折算 |
| 可复用知识的处理工单量 | 3,600 单/年 | 假设占全部工单的 30% |
| 人日 | 8 小时 | 用于报表制作工时换算 |
| 首年建设投入 | 20 万元 | 示例预算，包含配置或开发、集成、迁移、培训，需询价确认 |
| 年度运行成本 | 8 万元 | 示例预算，包含软件或云资源、维护及可选 AI 服务，需核实计费和工作量 |

### 4.2 年度收益汇总

年度产能价值 = 年业务量 × 单次节省人工分钟数 ÷ 60 × 人力小时成本。

| 收益来源 | 计算方式 | 年度产能价值 |
| :--- | :--- | ---: |
| 信息采集与补充 | 12,000 ×（10－4）÷ 60 × 100 | 12.00 万元 |
| 分类与派单 | 12,000 ×（8－2）÷ 60 × 100 | 12.00 万元 |
| 知识辅助诊断处理 | 3,600 ×（60－40）÷ 60 × 100 | 12.00 万元 |
| 催办与进度答复 | 12,000 ×（6－2）÷ 60 × 100 | 8.00 万元 |
| 月报制作 | 12 ×（2－0.5）× 8 × 100 | 1.44 万元 |
| **合计** | **年度释放约 4,544 小时** | **45.44 万元** |

各环节节省时间必须互斥记录：信息补充、派单、诊断处理、进度答复分别归集；月报制作只统计管理报表工时。审批催办、返工减少、员工停工减少和自助解决收益未纳入合计，以避免重复或缺乏依据的计量。

### 4.3 投资价值判断

- 在全部改善目标实现、首年全年运行的假设下，首年产能价值扣除示例建设及运行成本为：45.44－20－8＝**17.44 万元**。
- 若首年仅实现 60% 的规划产能价值，则为：45.44 × 60%－20－8＝**－0.736 万元**，说明采用率和上线节奏会明显影响首年投入产出。
- **产能价值不等于现金节约。** 只有实际减少外包费用、加班或新增招聘等支出，才能认定对应现金节省；释放的时间用于其他工作时，应表述为服务能力提升。
- 实际投资决策须以真实工单量、抽样工时、产品报价、实施周期和采用率重新测算；本文件不将潜在风险损失减少作为确定收益。

## 五、建设范围与落地顺序

| 阶段 | 业务范围 | 交付重点 |
| :--- | :--- | :--- |
| 一期：打通服务闭环 | 统一入口、服务分类、工单流转、规则派单、必要审批、SLA、通知、确认关闭、评价、基础报表、角色权限与审计记录 | 无需依赖 AI 即可完成一次完整服务流程；明确负责人和时限 |
| 二期：提高处理效率 | 已审核知识库、知识推荐、截图识别、分类建议、工单摘要、员工自助问答 | 根据试点准确性、知识覆盖和维护成本决定是否启用 AI |
| 后续按需扩展 | 资产管理深度集成、监控告警联动、账号自动开通与回收 | 单独评估接口、授权、审批控制和业务收益 |

一期不承担完整资产生命周期管理、采购库存管理或无人审核的自动修复。现有组织架构、身份认证、设备目录及消息渠道能否对接，应在实施前确认；暂不具备接口时可使用受控导入和人工执行留痕。
