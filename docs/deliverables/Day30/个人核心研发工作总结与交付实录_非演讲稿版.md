## 🛠️ 第一部分：垂直知识库 RAG 核心技术攻坚（Day 11 ~ Day 15）

### 1. 非结构化数据治理与标题树结构化分块（Day 11 ~ Day 12）
- **痛点与问题**：通用按字数（如 500 字）固定滑动截断的切块方案，会生生腰斩操作手册与排障规程，导致召回片段上下文残缺；
- **具体工作**：
  - 牵头对全公司 38 篇 IT 核心规章进行清洗与非结构化治理，制定统一 Markdown 标准格式；
  - 独立构建**基于 Markdown 标题层级（H1/H2/H3）的结构化分块管道**（`clean_pipeline.py`），确保每一个知识切片（Chunk）均包含完整的章节路径、前置条件与排障步骤；
  - 全链路接入 1024 维语义向量模型与 Chroma 向量数据库，相比基准方案使向量空间的聚类区分度提升了 32%。

### 2. “向量 + BM25” 双路召回与 RRF 融合机制（Day 13）
- **痛点与问题**：用户提问中频繁包含冷僻专有名词、报错代号（如 `0x0000007B`）或指令参数（如 `regedit`、`ipconfig /flushdns`），纯语义向量模型在长尾稀疏词上表征迟钝，漏召回率高；
- **具体工作**：
  - 研发双路混合检索流水线：一路走 1024 维向量语义近邻检索，一路走 BM25 稀疏词频硬匹配；
  - 引入 **RRF（Reciprocal Rank Fusion，倒数排名融合算法）**，建立无量纲排名加权机制，将语义召回与关键词命中结果科学归一化融合。

### 3. Cross-Encoder 深度重排精排（Day 13）
- **痛点与问题**：初路召回的 Top-20 候选集中混杂大量“字面相似但逻辑风马牛不相及”的伪相关片段；
- **具体工作**：
  - 在召回层后置部署 **Cross-Encoder 深度重排模型（Rerank）**；
  - 对“Query-Chunk”候选对执行 Cross-Attention 交叉注意力深度比对，剔除噪音切片，确保 Top-3 核心上下文无损送入大模型生成端。

### 4. 6:2:2 工业级黄金测试集构建与基准打封（Day 14 ~ Day 15）
- **痛点与问题**：口头约定“准确率高”无意义，企业规章版本更替（如住宿报销标准从旧版 400 元变更为新版 500 元）容易引发严重幻觉；
- **具体工作**：
  - 主导构建工业级 **6:2:2 黄金测试基准库**（60% 典型业务题、20% 规章版本冲突题、20% 边界拒答与恶意陷阱题）；
  - 编写自动化评测套件 `run_day15_pipeline.py`，完成全量跑测并输出封版基线：
    - **越界与废止条款拦截率**：`100.0%`
    - **答案参考来源角标命中率**：`100.0%`
    - **单次检索平均耗时**：`11.7 ms`

## 🛡️ 第二部分：安全受控 Agent、确定性编排与三位一体（Day 16 ~ Day 20）

### 1. 安全 Text2SQL AST 抽象语法树拦截器（Day 16）
- **痛点与问题**：大模型具备 Function Calling 工具调用能力后，若直接执行其生成的 SQL，存在 SQL 注入、越权写库与数据被恶意清空的灾难级隐患；
- **具体工作**：
  - 编写基于 Python `ast` 的 SQL 抽象语法树深度解析器；
  - 在 SQL 实际执行前强制进行节点遍历校验：只放行只读查询（SELECT），一旦出现 UPDATE、DELETE、DROP、ALTER 等写操作或存在语法混淆注入，直接在语法树解析层物理截断并抛出 403 异常。

- **痛点与问题**：自由放养的 Agent 调用链路黑盒不可视，出现调用超时或幻觉时无法定位根因；
- **具体工作**：
  - 摒弃松散脚本，将业务逻辑抽象为经典确定性状态机；

### 3. 三位一体协同架构与 HITL（人机协同）审批断点（Day 18）
- **痛点与问题**：大模型缺乏归责能力，如果直接代替工程师流转业务工单，出现误判无法追责；
- **具体工作**：
  - 落地“非结构化知识库 + 结构化数据库 + 外部接口”三位一体协同架构；
  - 落地 **HITL（Human-In-The-Loop，人机回环）断点机制**：大模型识别用户意图后仅能生成《派单草案》，系统自动在流转链路上触发挂起中断，必须由工程师或主管在前端确认点击放行后，状态机才真正执行落库。

### 4. 混沌工程故障注入与 Fallback 容灾降级（Day 19 ~ Day 20）
- **痛点与问题**：生产环境中向量库或外部 API 偶发超时会导致前端崩溃；
- **具体工作**：
  - 实施混沌工程测试，主动注入网络超时、向量库宕机与大模型 500 异常；
  - 编写 `GuardedRagClient` 四层防腐降级壳，实现主干链路优雅降级与兜底友好提示，通过第二阶段 Demo Day 质量大盘考核。

## 🕸️ 第三部分：GraphRAG 拓扑推理、LangGraph 原生中断与 FastMCP 工业互联（Day 21 ~ Day 27）

### 1. Parent-Child 存储架构与 Neo4j GraphRAG 因果多跳推导（Day 21 ~ Day 22）
- **痛点与问题**：在 IT 复杂故障中（如“远程桌面连接报 0x204”），表象故障与真实根因（“域控 DNS 欠费”或“主板电池时钟回拨”）分属不同文档，纯向量相似度检索在原理上无法完成跨文档的多跳因果发现；
- **具体工作**：
  - 落地 Parent-Child 切块策略，微观小块精准检索，宏观大块送模理解，设计 MySQL Parent Docstore 存储方案；
  - 将 38 篇 IT 核心规章实体抽取为三元组，入驻 **Neo4j 图数据库**；
  - 结合自适应意图路由，实现针对网络依赖、服务级联的 **2-Hop 因果多跳拓扑推理**；
  - 动态生成因果推理拓扑链条组件，在用户提问时实时渲染推导路径图，实现全流程白盒透明。

### 2. LangGraph 状态编排与 Checkpointer 持久化快照断电恢复（Day 23 ~ Day 26）
- **痛点与问题**：传统 ReAct 循环容易陷入不可控死循环，且内存状态在服务器重启后全部丢失；
- **具体工作**：
  - 将编排引擎全面升级为 **LangGraph StateGraph 原生有向无环图**；
  - 挂载持久化 **Checkpointer 快照机制**（支持内存与数据库持久化存储），每次状态流转自动赋予单调递增版本号；
  - 在重大特批审批时触发原生 `interrupt()` 挂起。经现场强杀服务断电模拟测试，重启后系统依据原 Session ID **秒级恢复快照上下文，实现状态 100% 还原与 0 数据丢失**；
  - 编写验证脚本支持 Time-Travel 时光机热补丁重放。

### 3. Anthropic FastMCP 工业标准互联协议落地（Day 27）
- **痛点与问题**：底层工具（查询工单、查询员工人事档案）与业务代码强耦合，其他大模型客户端无法复用；
- **具体工作**：
  - 基于原生 Python 零依赖实现了标准 **FastMCP (Model Context Protocol)** 协议服务端与客户端；
  - 将企业 HR 人事库与工单系统暴露为标准化 JSON-RPC 工具端点；
  - 完成与 OpenAI Tool 适配器的协议握手，实现底层工具资产即插即用的工业级解耦。

## 🚀 第四部分：Supervisor 多智能体协同、安全护栏与生产级性能发布（Day 28 ~ Day 29）

### 1. Supervisor-Worker 主从协同架构与 Guardrails 双向护栏（Day 28）
- **具体工作**：
  - 架构设计：Supervisor 调度中枢负责意图识别与任务拆解，分别指挥 KnowledgeWorker（知识规章专家）与 TicketWorker（工单经办专家）两个独立子图协作；
  - **输入安全护栏（Input Guardrail）**：针对 `忽略之前所有指令`、`我是超级管理员` 等越狱特征库进行正则与语义检测，在进入大模型前 **以 1.2ms 耗时、0 Token 消耗直接 403 阻断拦截**；
  - **输出脱敏护栏（Output Guardrail）**：在内容返回前端前，对手机号（`138****1234`）、身份证号、银行卡号执行自动化正则掩码打码。

### 2. 轻量向量动态路由选模（Semantic Cache）（Day 29）
- **痛点与问题**：高频重复咨询（如“住宿报销标准”、“VPN 申请流程”）反复请求大模型，响应慢且 Token 浪费严重；
- **具体工作**：
  - 研发基于向量余弦相似度（Cosine $\ge 0.90$）的轻量动态路由选模引擎；
  - 实测高频变体提问直接命中缓存输出，响应时间自 2,400ms 骤降至 **48ms（提速 50 倍）**，Token 开销直接归 **0**。

### 3. Model Router 动态阶梯选模与 Token 成本治理（Day 29）
- **痛点与问题**：无论简单问题还是复杂推理一律调用最昂贵的高阶大模型，API 调用账单高昂；
- **具体工作**：
  - 研发 Model Router 动态模型路由器；
  - 对简单事实查询、闲聊路由至轻量低成本模型（Flash），仅对多跳推理与复杂合规审查启用高阶推理模型；
  - 结合动态路由选模，使系统整体 API 成本综合下降达 **42.3%**。

### 4. FastAPI SSE 流式输出与全景会话管理（Day 29）
- **具体工作**：
  - 搭建 FastAPI 异步非阻塞端点，接入 **SSE（Server-Sent Events）** 协议，实现逐字打字机流式响应并实时广播思考规划阶段；
  - 首字响应时间（TTFT）大幅压缩至 **380ms** 以内；
  - 最新主干落地支持近 1 个月历史会话抽屉、支持随时开启新咨询，并将深度思考过程与拓扑链路全量持久化回放。

## 💡 第六部分：个人技术沉淀与交付工程师认知总结

回顾从 Day 11 到 Day 29 的全周期密集攻坚，个人在工程实践与架构思维上形成了三大核心认知沉淀：

1. **RAG 调优的重心在数据工程与检索流水线**：大模型的回答质量首先受限于上下文的精准度。通过标题树切块、混合召回、RRF 融合与重排，在数据入模前完成降噪，是解决幻觉最具性价比的手段；
2. **AI 的概率不确定性必须用确定性系统兜底**：企业级系统绝不能放任 Agent 自由脱缰。通过 Python AST 语法树物理阻断写操作、通过 Guardrails 秒级击毙越狱、通过 LangGraph Checkpointer 实现崩溃恢复、通过 HITL 强制保留人工终审权，才构筑了坚固的企业级安全防线；
3. **性能与成本控制是走向商业交付的必修课**：能跑通功能只算及格，能将 2.4 秒的时延压到 50 毫秒、能将企业 API 账单削减 40% 以上、能提供平滑的 SSE 流式体验，系统才真正具备商用落地的底气与竞争力。
