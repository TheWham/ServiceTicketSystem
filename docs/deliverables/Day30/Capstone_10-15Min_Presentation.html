SECURITY & DEFENSE · 守护生产数据库红线

大模型生成的代码等同于黑客脚本！——AST 抽象语法树物理只读拦截

❌ 惊魂一刻：大模型自主写 SQL 的越权与删库灾难

• 自鸣得意的惊醒：刚跑通大模型查工单自以为搞定，反向诱导测试“把工单状态改成已结案”，模型竟老老实实生成 UPDATE 语句！
• 生产级安全灾难：如果直接裸连真实生产库，业务数据将被恶意篡改或破坏，酿成 P0 事故；
• 正则黑名单形同虚设：只要用 SQL 注释（如 /**/UPDATE/**/）就能轻易绕过过滤，Prompt 提示词更是防君子不防黑客。

🛡️ 物理级防御：Python AST 语法树应用层只读熔断

• 语法树对象解析：执行前将生成的 SQL 字符串解析为 AST 抽象语法树对象，遍历所有语句节点；
• 只读节点白名单：强制仅放行 SELECT 语法节点与指定只读表名，杜绝越权访问；
• 物理级直接截断：一旦遍历到 UPDATE、DELETE、INSERT 或 DROP，0 Token 毫秒级直接抛出 403 异常；
• 实测防御成效：物理级 100% 杜绝数据库篡改与越权注入，构筑坚不可摧的底层安全底座。
💡 工程师认知蜕变：安全绝不能靠跟大模型讲礼貌！大模型生成的任何代码本质上都是不可信的外部输入；绝不能寄希望于 Prompt 约束或脆弱的正则过滤，必须在底层代码和 AST 语法树层面完成物理级截断！

❌ 传统检索盲区：看不清长链因果关系

• 传统检索误诊：纯向量检索只能看到冰山一角，只能召回远程桌面或网络配置，驴唇不对马嘴，彻底误诊。

摆脱不可控的“死循环”与“丢会话”——LangGraph 状态图与 Checkpointer 断电自愈

告别死循环：有向无环状态图编排 (StateGraph)

• 无状态 ReAct 崩溃：工具变多后死循环频发，模型在多个工具间反复横跳，步数失控；
• 强类型状态契约：全局 State 字典严格定义业务状态，Supervisor 条件边根据状态精准流转；
• 硬熔断与时空旅行：严格步数熔断杜绝死循环，支持 Time-Travel 时光机热补丁与局部重放测试。

持久化快照自愈：Checkpointer 抵御极端宕机

• 服务重启会话全丢：早期后端一重启或网络抖动，用户聊了半天的会话全丢，客户体验极差；
• 原生 interrupt 挂起：审批与特批流转时优雅挂起，状态快照打上版本号持久化落库；
• 断电强杀实测：kill -9 强杀后台进程，重启服务传入 Session ID，快照秒级唤醒，状态 100% 还原，零数据丢失！

DEEP REFLECTION & SELF-CRITIQUE · 工程师的自我革命

不讲客套话：我在一个月实战中暴露的三大核心不足与深刻反省

不足 01 · 盲目信任

盲信 AI 与偷懒心理

• 误把自然语言当银弹：初期总觉得大模型无所不能，产生偷懒心理，盲信并直接 Copy-Paste AI 生成的代码；
• 缺乏逐行审校意识：不去推演底层时序逻辑与边界条件，误以为“能跑通就是对的”；
• 惨痛教训：早期代码遭遇大面积业务幻觉与高危数据误改，险些酿成生产事故。
不足 02 · 被 AI 牵制

代码不熟被 AI 牵着走

• 缺乏底层排查定力：遇到复杂 Bug 时没有静下心打断点、看时序日志，习惯性把报错全甩给 AI；
• 盲目跟随 AI 瞎猜乱改：AI 瞎猜一个解法就跟着试，改完引出三个新 Bug，深陷“报错-乱改-腐化”的死循环；
• 惨痛教训：代码被改得面目全非、时序严重错乱，一度沦为被 AI 牵着鼻子走的被动调试员。
不足 03 · 缺乏架构定力

试图用 Prompt 碰运气

• 边界意识严重薄弱：初期遇到状态漂移和幻觉，第一反应竟是疯狂叠 Prompt，试图用自然语言“感化”模型；
• 轻视工程确定性：忽略了状态机、关系型事务和防御门禁的刚性约束，把严肃的商业逻辑托付给概率；
• 惨痛教训：多轮交互中上下文丢失和逻辑失控，暴露出自己工程架构思维的极度匮乏。
💡 深刻反省：如果不把底层代码原理与工程骨架吃透，盲信 AI 带来的绝不是提效，而是指数级加倍的技术债务；只有人具备了独立排查 Bug、主导架构和审判代码的能力，AI 才是真正的生产力放大器！
