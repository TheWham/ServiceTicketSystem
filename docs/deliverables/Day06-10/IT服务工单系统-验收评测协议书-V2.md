# 企业 IT 服务工单系统 —— 验收评测协议书

---

## 一、总述

### 1.1 评测目的

在系统当前进度基础上，对以下五条主链路进行量化验收，明确核心指标、测试样本与判定标准，确保交付质量可度量、可回溯、可签字：

1. **提单链路**：七字段校验 → 幂等建单 → 落库一致性；
2. **流转链路**：9 态状态机全边流转 → 工程师接单/处理 → 验收闭环；
3. **调度链路**：分类路由 → 加权负载派单 → 异常队列兜底；
4. **SLA 与通知链路**：工作日历计时 → 超时流转 → 事件驱动通知；
5. **智能链路**：RAG 知识摄入与生命周期管理 → AI 咨询 → 转人工 → 咨询转工单。

### 1.2 评测范围

| 阶段 | 范围内（必测） | 范围外（本次不测） |
| :--- | :--- | :--- |
| 提单 | 七字段校验、幂等键、草稿、落库一致性 | — |
| 流转 | 状态机、角色路由、乐观锁、流转日志、主管删除工单（级联清理） | — |
| 调度 | 分类路由、组内加权负载派单、接单矩阵（影响×紧急）、新建工程师自动入组、异常队列 | — |
| SLA/通知 | 优先级 SLA（高 4 工作小时/中 1 工作日/低 3 工作日）、工作日历、暂停不计时、超时自动流转、9 态事件通知（1 分钟幂等）、30s 轮询未读 | 短信/邮件外部通道（本期站内通知为准） |
| AI/RAG | 知识上传→解析→切片→向量化→ES 入库、生命周期状态机（DRAFT→REVIEW→PUBLISHED→OFFLINE）、自审拦截、知识检索、AI 咨询、反馈、转人工、咨询转工单草稿 | 模型生成质量的人工主观评分（以检索命中与引用正确性替代） |
| 安全 | JWT 鉴权、角色越权、XSS/SQL/路径穿越/伪造附件注入 | 渗透压测（超出本期培训验收范围） |

### 1.3 评测环境

- 前端：Vue 3 + Vite + Pinia + Element Plus，端口 5173，proxy `/api → 8080`
- 后端：Java 17 + Spring Boot 3.2.5 + Spring Cloud 2023.0.1（Nacos 注册/配置、OpenFeign、Gateway）
  - gateway `:8080`（唯一入口 + JWT 统一鉴权）
  - user-service `:8101`（登录/JWT/账号/草稿）
  - ticket-service `:8201`（工单全业务/状态机/路由/SLA/通知/异常队列）
  - consultation-service `:8301`（AI 咨询/转人工/知识检索，密钥经 `ai-secrets.yml` 或 `AI_API_KEY` 注入）
  - rag-service（文档摄入/切片/向量化/知识生命周期，ES 8.11.3）
- 数据库：MySQL 8 统一远程库 `it_ticket_system`（28 张表），ORM MyBatis-Plus 3.5.7
- 检索：Elasticsearch 8.11.3（`:9200`）+ Kibana（`:5601`）
- 认证：JWT（HS256，12h）+ BCrypt；种子账号 4 个（EMPLOYEE/ENGINEER/PLATFORM_ADMIN/KNOWLEDGE_ADMIN，密码 `123456`）
- **数据安全约定**：远程库只增不删，验收全程禁止 DROP/TRUNCATE/DELETE 表级操作；主管删单功能仅允许在专用演示数据上验证。

## 二、核心评测指标体系

指标共 **16 项**，覆盖提单、流转、调度、SLA/通知、AI/RAG 与安全六条链路，权重合计 100%。

### 2.1 指标总览表

| 编号 | 指标名称 | 归属链路 | 权重 | 验收门禁 | 生产运行基线 | 测量方法 | 判定依据 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **M-01** | 字段校验用例通过率 | 提单 | 8% | 100% | — | 样本集逐字段比对预期/实际拦截 | 校验规则为确定性代码逻辑，断言失败即缺陷 |
| **M-02** | 分类值域用例通过率 | 提单 | 4% | 100% | — | category 枚举值域 + 叶子分类接口一致性 | 枚举值域为确定性校验，失败即缺陷 |
| **M-03** | 字段提取用例通过率 | 提单 | 8% | 100% | — | 落库字段与提交字段逐字段比对 | 落库为确定性写入，字段不一致即数据缺陷 |
| **M-04** | 响应延迟 | 全链路 | 6% | 见 §2.2.4（P95/P99） | 同验收阈（APM 持续监控） | 埋点计时 P95/P99 | 内网事务系统与 LLM 应用的常见分位响应水位 |
| **M-05** | 受测样本建单成功率 | 提单 | 6% | 100% | ≥ 99.95% | 校验通过样本中成功落库占比 | 验收为样本落库断言；生产考虑网络抖动与锁开销 |
| **M-06** | 幂等防重用例通过率 | 提单 | 6% | 100% | ≥ 99.99% | idempotency_key 重复提交拦截率 | 唯一约束+幂等键拦截，重复建单属资损级缺陷；生产允许极小毛刺 |
| **M-07** | 降级用例验证通过率 | 智能链路 | 5% | 100%（Mock 回放） | ≥ 99.5% | RAG/AI 依赖异常时提单与咨询主链路可用 | Mock 故障注入下兜底行为为用例断言；生产熔断探测存在窗口抖动 |
| **M-08** | 附件校验用例通过率 | 提单 | 3% | 100% | — | 格式/大小/数量 | 四维校验为确定性规则，防伪造上传属安全红线 |
| **M-09** | 资产编号校验用例通过率 | 提单 | 2% | 100% | — | 正则 + CMDB 联动校验 | 正则+CMDB 联动为确定性校验 |
| **M-10** | 状态机流转正确率 | 流转 | 12% | 100% | 100%（违规零容忍） | 18 条合法边放行 + 非法边拒绝 + 流转日志完整 | 越权与非法跃迁属 P0 级业务安全缺陷，零容忍 |
| **M-11** | 自动路由用例通过率 | 调度 | 10% | 100% | — | 路由命中支持组 + 负载均衡选人正确率 | 路由配置匹配与加权选人均为确定性逻辑 |
| **M-12** | SLA 计时准确率 | SLA/通知 | 10% | 100% | 工单级 SLA 达成率 ≥ 95% | 工作日历/节假日/暂停段的剩余工时计算 | 计时为确定性计算；生产达成率受排班等运营因素影响 |
| **M-13** | 通知送达用例通过率 | SLA/通知 | 6% | 100% | ≥ 99.9% | 事件→接收人推导→落库→幂等去重 | 接收人推导与幂等去重为确定性逻辑；生产毛刺来自中间件抖动 |
| **M-14** | 知识生命周期合规率 | AI/RAG | 8% | 100% | 100%（合规零容忍） | 状态机守卫（自审拦截等）+ ES 联动一致性 | 权限合规红线（自审拦截/未发布不可见），零容忍 |
| **M-15** | RAG 检索与引用准确率 | AI/RAG | 8% | Top-3 命中 ≥ 85% 且引用合规 100% | Top-3 命中 ≥ 80% 且引用合规 100% | golden dataset 回放 + AI 引用均来自已发布知识 | 语义检索为概率性链路，按行业金标集水位定阈；引用合规为合规红线 |
| **M-16** | 咨询闭环用例通过率 | AI/RAG | 4% | 100% | ≥ 99% | AI 咨询→（反馈/转人工/转工单）全流程无中断完成率 | 流程闭环为系统行为断言；生产中断多来自模型超时（计入 M-07） |

**阈值设定依据**：

- **验收门禁：确定性逻辑零容忍**：规则校验、枚举值域、落库一致性、幂等、状态机、路由规则匹配、SLA 计时、通知去重、知识生命周期守卫均为确定性代码逻辑，样本回放中任何一条断言失败即为缺陷，故验收门禁一律 100%，不设"容错率"；
- **验收门禁：概率性链路按行业基线**：语义检索命中、模型首字节延迟结果天然有波动，阈值按金标数据集回放与分位统计设定——企业内部 RAG 应用金标集 Top-3 命中率的常见验收水位为 85%~90%，本协议取 85%；引用合规属合规约束，取 100%；
- **延迟阈值对齐企业内部系统基线**：单次内部服务查询 P95 ≤ 500ms、核心写接口 P95 ≤ 1s / P99 ≤ 2s、ES 混合检索 P95 ≤ 800ms、LLM 首字节 P95 ≤ 3s，均为企业内网事务型系统与 LLM 应用的常见响应时间水位；
- **生产运行基线（SLO）列**：为上线后运维度量参考（可用率、成功率、SLA 达成率等），遵从运维规范，不参与本次验收判定；SLO 列留「—」者，表示该项为确定性代码逻辑，无单独生产基线，并入系统整体可用率度量。

### 2.2 指标详细定义

#### 2.2.1 M-01 字段校验用例通过率

- **定义**：对七字段校验规则执行的正确率，非法被拦截 与 合法被放行。
- **计算公式**：

  ```
  M-01 = (正确拦截的非法输入数 + 正确放行的合法输入数) / 总校验断言数 × 100%
  ```

- **拆分子项**：title 必填+长度、category 必填+值域、priority 必填+值域、description 必填+长度上限 500 字、attachment 格式+大小+数量、expected_finish_time ≥ 当前时间、asset_id 正则+CMDB。
- **误判分级**：非法漏拦权重 ×2，合法误拦权重 ×1——漏拦比误拦危害更大。

#### 2.2.2 M-02 分类值域用例通过率

- **定义**：用户所选 category 落入合法叶子分类的比率；前端下拉与 `GET /api/v1/categories/leaf` 返回值（统一 snake_case 归一化）一致。
- **计算公式**：

  ```
  M-02 = (category ∈ 合法叶子分类的样本数 / 总样本数) × 0.6 + (下拉渲染正确数 / 应渲染数) × 0.4
  ```

#### 2.2.3 M-03 字段提取用例通过率

- **定义**：校验通过并生成工单后，落库 `ticket` 表各字段值与用户提交值逐字段一致的比例。
- **计算公式**：

  ```
  M-03 = Σ(各字段匹配数) / (成功工单数 × 字段数) × 100%
  ```

- **字段权重**：title 0.2、category 0.2、priority 0.15、description 0.25、asset_id 0.1、attachment_urls 0.05、expected_finish_time 0.05。
- **关键校验点**：description 是否被错误截断、attachment_urls 是否正确序列化为 JSON List、时间持久化统一 UTC 且 HTTP 输出带时区。

#### 2.2.4 M-04 响应延迟

分四个子项，分别设阈：

| 子项 | 定义 | 目标 P95 | 目标 P99 | 测量起止点 |
| :--- | :--- | :--- | :--- | :--- |
| M-04a 失焦校验延迟 | asset_id 失焦调 CMDB 校验耗时 | ≤ 500ms | ≤ 1000ms | blur 事件 → 校验结果回显 |
| M-04b 提交端到端延迟 | 点击 submit 到跳转成功页（经网关+路由） | ≤ 1000ms | ≤ 2000ms | click → 路由跳转完成 |
| M-04c 知识检索延迟 | 知识搜索接口端到端（含 ES 查询） | ≤ 800ms | ≤ 1500ms | 请求发出 → 结果渲染 |
| M-04d AI 首字节延迟 | AI 咨询请求到首个回复到达 | ≤ 3000ms | ≤ 5000ms | 发送 → ai-messages 响应 |

- **综合公式**：`M-04 = 0.25×达标(M-04a) + 0.25×达标(M-04b) + 0.25×达标(M-04c) + 0.25×达标(M-04d)`，各子项达标记 1，未达标记 0。

#### 2.2.5 M-05 受测样本建单成功率

- **定义**：前置校验通过的样本中，成功落库并生成合法 ticket_id、初始状态合法的比例。
- **计算公式**：

  ```
  M-05 = 成功生成工单数 / 校验通过样本数 × 100%
  ```

- **合法性校验**：ticket_id 符合发号规则、creator_id=当前登录用户、created_at 落在合理区间；创建后自动路由（命中路由规则则进入 ASSIGNED，无候选则留 NEW 并进入异常队列）。
- **说明**：验收门禁要求受测样本全部成功；生产环境建单成功率基线见 §2.1 生产运行基线（SLO）列（≥ 99.95%，由运维侧 APM/日志度量）。

#### 2.2.6 M-06 幂等防重用例通过率

- **定义**：携带相同 idempotency_key 的重复提交被拦截且仅生成一条工单的比率（错误码 `40901`）。
- **测试方式**：同一合法样本带同一幂等键并发/快速重发 5 次，预期仅落库 1 条。
- **计算公式**：`M-06 = 仅生成1条的样本数 / 重复提交样本数 × 100%`。

#### 2.2.7 M-07 降级用例验证通过率

- **定义**：RAG 检索或 AI 模型依赖超时/异常时，主链路仍可用的比率：
  - 知识检索异常不阻塞提单；
  - AI 咨询走熔断降级（`GuardedRagClient` + `SimpleCircuitBreaker`），返回兜底应答而非 500；
  - ES 不可用时知识生命周期操作给出明确错误且不破坏 MySQL 数据一致性（发布切片写 ES 失败标待补偿、不回滚业务事务）。
- **测试方式**：Mock 依赖返回 500/超时 3s；参照已有网关/工单/用户服务脏数据与降级兜底测试集回放。
- **计算公式**：`M-07 = 降级场景下主链路成功数 / 降级场景样本数 × 100%`。

#### 2.2.8 M-08 附件校验用例通过率

- **定义**：对附件格式（jpg/png）、单张大小（≤5MB）、数量（≤3张）正确率。
- **计算公式**：`M-08 = 正确判定数 / 附件校验断言数 × 100%`。

#### 2.2.9 M-09 资产编号校验用例通过率

- **定义**：asset_id 正则 `^IT-[A-Z]{2,4}-\d{8}$` 校验与 CMDB 联动校验（查无提示、查中回显型号与责任人）的综合正确率。
- **计算公式**：`M-09 = (正则正确数 + CMDB 联动正确数) / 总断言数 × 100%`。

#### 2.2.10 M-10 状态机流转正确率

- **定义**：工单 9 态 18 边状态机（NEW → ASSIGNED → IN_PROGRESS → PENDING_SUPPLEMENT ⇄ / PENDING_EXTERNAL ⇄ / PENDING_ACCEPTANCE → COMPLETED / CANCELLED / CLOSED）的执行正确率：
  - 全部合法边在正确角色+守卫条件下放行，并写入 `ticket_transition` 日志；
  - 非法边（含角色越权、非本人操作、缺 remark、乐观锁冲突）一律拒绝（`40910/40911/40912`）；
  - 系统自动边正确触发：响应超时转派、72h 未补充自动关闭、48h 未验收自动通过、7 日内复发重开；
  - 主管删除工单时级联清理全部关联表数据，无孤儿记录。
- **计算公式**：`M-10 = 正确流转断言数 / 总流转断言数 × 100%`，阈值 100%（状态机错误不可容忍）。

#### 2.2.11 M-11 自动路由用例通过率

- **定义**：工单创建后按 `category_route` 路由规则定位支持组、组内按加权负载选择工程师的正确率；新建工程师账号自动加入全部 ACTIVE 支持团队后可被自动派单。
- **判定要点**：
  - 路由命中：不同分类工单派往其配置的支持组；
  - 负载均衡：多名候选时选中加权负载最优者，不长期集中派给单人；
  - 兜底：无可用候选人时工单留 NEW、进异常队列且管理员可见待处理数；
  - 新工程师：建号后无需人工排班即进入派单候选池。
- **计算公式**：`M-11 = 路由正确样本数 / 路由样本总数 × 100%`，阈值 100%（路由规则匹配与加权选人均为确定性配置逻辑）。

#### 2.2.12 M-12 SLA 计时准确率

- **定义**：SLA 实例按优先级生成（高 4 工作小时/中 1 工作日/低 3 工作日），基于工作日历（`work_calendar` + 节假日表）只计工作时间、暂停时段（`sla_pause`）不计入的计算正确率。
- **判定要点**：跨周末/节假日的目标时刻推算；暂停-恢复后剩余工作秒连续不跳变；超时自动转入异常处理；前端 SlaBadge/SlaTimer 以服务端剩余工作秒为基准倒计时，误差 ≤ 60s。
- **计算公式**：`M-12 = 计时断言正确数 / 总计时断言数 × 100%`，阈值 100%。

#### 2.2.13 M-13 通知送达用例通过率

- **定义**：9 态流转事件驱动通知（分配/接单/请求补充/验收/超时等），接收人按目标状态推导正确、以 `event_id+receiver+channel` 生命周期幂等键去重的比率。
- **判定要点**：接收人不缺不多；同一事件重放不产生重复通知；未读计数与 30s 轮询接口一致；点击通知按角色跳转对应工作台并打开详情。
- **计算公式**：`M-13 = 通知断言正确数 / 总通知断言数 × 100%`，阈值 100%。

#### 2.2.14 M-14 知识生命周期合规率

- **定义**：RAG 知识文章四态状态机（DRAFT → PENDING_REVIEW → PUBLISHED → OFFLINE）的守卫与检索可见性合规率：
  - 仅 DRAFT 可提审；驳回必须填原因；流转审计不可篡改；
  - **AC-25 自审拦截**：提交人不得审核自己的文章；
  - 高风险知识发布须平台管理员；
  - 乐观锁防并发审核冲突；
  - **AI-001**：未发布内容（草稿/待审）不得进入 ES 检索与 AI 引用；下线后 ES 切片置 OFFLINE，搜索/AI 立刻不可见（AC-27）；
  - 发布时切片写 ES 失败标待补偿，不回滚业务事务。
- **计算公式**：`M-14 = 合规断言正确数 / 总合规断言数 × 100%`，阈值 100%。

#### 2.2.15 M-15 RAG 检索与引用准确率

- **定义**：对已发布知识库，知识检索 Top-3 结果中包含期望文档的比率，以及 AI 咨询回复引用来源 100% 来自已发布知识的比率。
- **测量方式**：使用 `evals/golden_datasets` 金标数据集回放，逐条比对期望命中与实际命中；AI 回复逐条检查引用（citation）指向的知识状态必须为 PUBLISHED。
- **计算公式**：

  ```
  M-15 = 0.6 × (Top-3 命中的金标样本数 / 金标样本总数) + 0.4 × (引用合规的 AI 回复数 / AI 回复样本数)
  ```

- **阈值**：Top-3 命中子项 ≥ 85%，引用合规子项 = 100%（引用未发布知识属红线）。

#### 2.2.16 M-16 咨询闭环用例通过率

- **定义**：AI 咨询会话全流程（发起 → AI 应答 → 用户反馈/转人工/一键转工单草稿 → 解决确认/重开/关闭）无中断完成的比例。
- **判定要点**：转人工后队列状态（queue-status）正确推进；转工单草稿（ticket-draft）字段预填正确，提交后走标准提单链路；咨询侧超时提醒与自动解决调度器按预期触发；Outbox 事件（EV-001 信封、aggregate_version 单调递增）正常发布。
- **计算公式**：`M-16 = 完整闭环会话数 / 总会话样本数 × 100%`，阈值 100%（模型侧超时走降级路径，计入 M-07，不计为闭环中断）。

### 3.2 流转与调度（TC-11 ~ TC-14）

#### TC-11 ｜ 全生命周期闭环（正向）

员工提交硬件工单 → 自动路由命中支持组并派单（NEW→ASSIGNED）→ 工程师接单（矩阵确认影响×紧急，ASSIGNED→IN_PROGRESS）→ 提交解决方案（→PENDING_ACCEPTANCE）→ 员工验收通过（→COMPLETED）→ 评价 5 星。
**预期**：每步状态合法、`ticket_transition` 逐条记录、对应通知逐条送达、SLA 实例状态随流转推进。

#### TC-12 ｜ 非法流转与角色越权（负向）

- 工程师对 NEW 工单直接提交解决方案（跳态）→ 拒绝 `40910`；
- 员工甲对员工乙的工单执行撤销 → 拒绝（非本人）；
- 普通员工调用派单接口 → 拒绝 `40300`；
- 工程师抢单已被他人领取的工单 → 拒绝 `40912`。
**预期**：全部拦截，状态不迁移，无流转日志写入。

#### TC-13 ｜ 自动路由与异常队列（正向+兜底）

- 新建工程师账号（不人工排班）→ 提交其能力分类工单 → 被自动派给该工程师（自动入组生效）；
- 提交一个无可用候选人的分类工单 → 留 NEW、进异常队列、管理员待处理数 +1 → 管理员人工改派后正常流转。
**预期**：路由命中、兜底可见、人工接管可恢复。

#### TC-14 ｜ 主管删除工单级联清理（正向+安全）

主管删除一张已完结演示工单 → 工单本体及流转日志、SLA 实例、暂停记录、通知、幂等记录等关联表数据级联清理，数据库无孤儿记录；非主管角色调用删除接口 → 拒绝。
**约束**：仅在专用演示数据上执行，遵守远程库「只增不删」约定之外的该受控例外。

**预期**：M-07 达标，无脏数据写入（对齐已有脏数据与降级兜底测试集）。

## 四、执行与判定

### 4.1 执行方式

1. **自动化回放**：提单链路（M-01~M-09、TC-01~TC-10）使用 `acceptance/` pytest 套件（27 项用例）与 `scripts/run_acceptance.py` 生成执行记录；
2. **服务端集成测试**：M-10~M-13 以 ticket-service / consultation-service 集成测试与手动脚本化验证（SQL 断言 + API 断言）结合；
3. **RAG/AI 回放**：M-14~M-16 以 `evals/golden_datasets` 金标数据集 + rag-service 7 个测试类（SM/AC/AI/MR/RD/EV/DM 规范条目对应）回放；
4. **前端走查**：四端页面（员工/工程师/主管 /知识库管理/咨询）按 TC 步骤人工走查并录屏留证。

### 4.2 通过判定

- **逐项判定**：16 项指标各自须达到目标阈值；确定性指标要求 100%，任何一条样本断言失败即判定该项不达标；
- **零容忍项**：M-06 幂等、M-08 附件 MIME 校验、M-10 状态机、M-12 SLA 计时、M-14 知识生命周期、M-15 引用合规子项，以及安全样本 TC-10/TC-12/TC-18——任一违反，整体验收直接判定不通过；
- **整体通过**：逐项判定全部达标且零容忍项无违反；
- **加权得分** = Σ(各指标实测达标率 × 权重)，仅用于验收报告中的质量分级（≥ 98 优秀、95 ~ 98 良好），不替代逐项阈值判定。
