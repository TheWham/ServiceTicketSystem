# 企业 IT 服务工单系统 —— 验收评测协议书

### 1.1 评测目的

本协议书用于在 P0 功能「统一工单提交入口」交付前，对其**前置字段校验**与**后置工单生成**两条链路进行量化验收，明确核心指标、测试样本与判定标准，确保上线质量可度量、可回溯、可签字。

### 1.2 评测范围（P0 边界）

| 阶段 | 范围内（必测） | 范围外（本次不测） |
| :--- | :--- | :--- |
| **前置：字段校验** | title / category / priority / description / attachment_urls / expected_finish_time / asset_id 七字段校验规则、提交按钮置灰与防抖、草稿自动保存 | 知识库推荐卡渲染（P0 阶段不展示） |
| **后置：生成工单** | 校验通过后落库、生成 ticket_id、ticket_status=CREATED、通知事件触发 | 工程师接单/流转/验收（属 F-02，非 P0） |

### 1.3 评测环境

- 前端：Vue3 + Vite + Element Plus，端口 5173
- 后端：Spring Boot 3.3.5（JDK 17），端口 8080，MyBatis-Plus
- 数据库：MySQL，表 `ticket` / `sys_user` / `ticket_category`
- 认证：JWT；资产校验依赖 CMDB 模拟数据

## 二、核心评测指标体系

本小组 P0 功能核心指标共 **9 项**，按"校验精确度 → 提取准确率 → 生成成功率 → 响应延迟 → 防护健壮性"分层定义，权重合计 100%。

### 2.1 指标总览表

| 编号 | 指标名称 | 归属链路 | 权重 | 目标阈值 | 测量方法 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **M-01** | 字段校验精确度 | 前置校验 | 20% | ≥ 98% | 样本集逐字段比对预期/实际拦截 |
| **M-02** | 分类精确度 | 前置校验 | 10% | 100% | category 枚举值域 + 推荐触发一致性 |
| **M-03** | 提取准确率 | 后置生成 | 20% | ≥ 99% | 落库字段与提交字段逐字段比对 |
| **M-04** | 响应延迟 | 全链路 | 15% | 见 §2.2.4 | 埋点计时 P95/P99 |
| **M-05** | 工单生成成功率 | 后置生成 | 15% | ≥ 99.5% | 校验通过样本中成功落库占比 |
| **M-06** | 幂等防重率 | 后置生成 | 10% | 100% | 3s 内重复提交拦截率 |
| **M-07** | 降级可用率 | 前置校验 | 5% | 100% | 推荐接口异常时提单仍可用 |
| **M-08** | 附件校验准确率 | 前置校验 | 3% | 100% | 格式/大小/数量/**MIME 校验** |
| **M-09** | 资产编号校验准确率 | 前置校验 | 2% | 100% | 正则 + CMDB 联动校验 |

注: **MIME 校验**就是不信任扩展名，而是去读文件头部魔数，判断它到底是不是真的图片。只看扩展名的校验叫"扩展名白名单"，能被轻易绕过。

### 2.2 指标详细定义

#### 2.2.1 M-01 字段校验精确度（Field Validation Accuracy）

- **定义**：对七字段校验规则执行的正确率，综合真阳性（非法被拦截）与真阴性（合法被放行）。
- **计算公式**：

  ```
  M-01 = (正确拦截的非法输入数 + 正确放行的合法输入数) / 总校验断言数 × 100%
  ```

- **拆分子项**：title 必填+长度、category 必填+值域、priority 必填+值域、description 必填+10~500 长度、attachment 格式+大小+数量、expected_finish_time ≥ 当前时间、asset_id 正则+CMDB。
- **误判分级**：假阴性（非法漏拦）权重 ×2，假阳性（合法误拦）权重 ×1——漏拦比误拦危害更大。

#### 2.2.2 M-02 分类精确度（Category Precision）

- **定义**：用户所选 category 落入合法枚举 `{HARDWARE, SOFTWARE, NETWORK, ACCOUNT, OTHER}` 的比率，且选中后 300ms 防抖触发知识库推荐的时机正确率。
- **计算公式**：

  ```
  M-02 = (category ∈ 合法枚举的样本数 / 总样本数) × 0.6 + (推荐触发时机正确数 / 应触发数) × 0.4
  ```

- **说明**：P0 阶段推荐卡不展示，仅校验触发时机与防抖，不校验推荐内容质量。

#### 2.2.3 M-03 提取准确率（Extraction Accuracy）

- **定义**：校验通过并生成工单后，落库 `ticket` 表各字段值与用户提交值逐字段一致的比例。
- **计算公式**：

  ```
  M-03 = Σ(各字段匹配数) / (成功工单数 × 字段数) × 100%
  ```

- **字段权重**：title 0.2、category 0.2、priority 0.15、description 0.25、asset_id 0.1、attachment_urls 0.05、expected_finish_time 0.05。
- **关键校验点**：description 是否被错误截断、attachment_urls 是否正确序列化为 JSON List、expected_finish_time 时区是否正确。

#### 2.2.4 M-04 响应延迟（Response Latency）

分三个子项，分别设阈：

| 子项 | 定义 | 目标 P95 | 目标 P99 | 测量起止点 |
| :--- | :--- | :--- | :--- | :--- |
| M-04a 失焦校验延迟 | asset_id 失焦调 CMDB 校验耗时 | ≤ 800ms | ≤ 1200ms | blur 事件 → 校验结果回显 |
| M-04b 推荐触发延迟 | category 选中到推荐请求发出（含 300ms 防抖） | 300~600ms | ≤ 800ms | change 事件 → 请求发出 |
| M-04c 提交端到端延迟 | 点击 submit 到跳转成功页 | ≤ 1500ms | ≤ 2500ms | click → 路由跳转完成 |

- **综合公式**：`M-04 = 0.3×达标(M-04a) + 0.3×达标(M-04b) + 0.4×达标(M-04c)`，各子项达标记 1，未达标记 0。

#### 2.2.5 M-05 工单生成成功率（Ticket Generation Success Rate）

- **定义**：前置校验通过的样本中，成功落库并生成合法 ticket_id、ticket_status=CREATED 的比例。
- **计算公式**：

  ```
  M-05 = 成功生成工单数 / 校验通过样本数 × 100%
  ```

- **合法性校验**：ticket_id 符合 `TK+14位日期+4位流水` 格式、ticket_status=CREATED、creator_id=当前登录用户、created_at 落在合理区间。

#### 2.2.6 M-06 幂等防重率（Idempotency Guard Rate）

- **定义**：提交按钮 3s 防抖期间，重复点击被拦截且仅生成一条工单的比率。
- **测试方式**：对同一合法样本在 3s 内连点 5 次，预期仅落库 1 条。
- **计算公式**：`M-06 = 仅生成1条的样本数 / 重复点击样本数 × 100%`。

#### 2.2.7 M-07 降级可用率（Fallback Availability Rate）

- **定义**：知识库推荐接口超时（>2s）或异常时，提单链路仍 100% 可用（不弹框、不阻塞、工单正常生成）的比率。
- **测试方式**：Mock 推荐接口返回 500/超时 3s，验证推荐卡静默隐藏且提单成功。
- **计算公式**：`M-07 = 降级场景下提单成功数 / 降级场景样本数 × 100%`。

#### 2.2.8 M-08 附件校验准确率（Attachment Validation Accuracy）

- **定义**：对附件格式（jpg/png）、单张大小（≤5MB）、数量（≤3张）、真实 MIME（防伪造扩展名）四维校验的正确率。
- **计算公式**：`M-08 = 正确判定数 / 附件校验断言数 × 100%`。

#### 2.2.9 M-09 资产编号校验准确率（Asset ID Validation Accuracy）

- **定义**：asset_id 正则 `^IT-[A-Z]{2,4}-\d{8}$` 校验与 CMDB 联动校验（查无提示、查中回显型号与责任人）的综合正确率。
- **计算公式**：`M-09 = (正则正确数 + CMDB 联动正确数) / 总断言数 × 100%`。

## 四、评测执行与记录

### 4.1 执行步骤

## 六、风险与注意事项

1. **CMDB 依赖**：TC-01/03/05/08 的资产编号校验依赖 CMDB 模拟数据，评测前必须灌库，否则 M-09 误判。
2. **时间敏感**：TC-08/TC-09 的 expected_finish_time 判定依赖系统当前时间，执行时需记录评测时刻。
3. **Mock 注入**：TC-10 的 SQL 注入验证不得在生产库执行，必须在隔离评测库，评测后核查 `ticket` 表完整性。
4. **延迟采样**：M-04 需采集 ≥20 次方可计算稳定 P95/P99，单次测量不具代表性。
5. **降级 Mock**：M-07 需 Mock 推荐接口，不得通过断网模拟（断网会同时影响 CMDB 校验，污染 M-09）。
