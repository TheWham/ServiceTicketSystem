# 错误 AADSTS50105 - 已登录的用户未被分配该应用程序的角色

## 概要

当企业应用程序要求分配时，如果请求访问的用户没有符合条件的分配，则会出现 AADSTS50105 错误。 本文介绍如何解决错误并还原用户访问。

分配检查可以应用于使用 SAML、OpenID Connect、OAuth 2.0、WS 联合身份验证或应用程序代理预身份验证的应用程序。

## 现象

当用户尝试登录到应用程序时，他们会收到以下错误：

> 错误 AADSTS50105 - 登录的用户尚未分配到该应用程序的角色。

## 原因

企业应用的服务主体已将 **是否需要分配？** 设置为 **是**，而发出请求的用户未被分配该应用程序的应用角色。

对于用户，访问权限可能来自以下任一分配：

- 将用户直接分配给应用程序。
- 将组分配给应用程序，并且用户是该组的直接成员。

当应用程序不公开命名应用程序角色时，对 **默认访问** 的分配满足分配要求。 但是， **默认访问** 不会向令牌添加 `roles` 声明。

Important

对于可预测的访问，不要依赖于嵌套组成员身份。 直接分配给该用户，或使用该用户直接所属的组。

注意

分配要求不适用于全局管理员。 全局管理员可以在没有分配的情况下登录，因此请与受影响的用户进行测试。

## 解决方法

使用可以更新企业应用程序属性和应用角色分配的帐户，例如云应用程序管理员、应用程序管理员或该应用程序服务主体的当前所有者。 基于组的分配需要Microsoft Entra ID P1 或 P2 许可证。

首先，确认应用程序是否应限制对已分配用户的访问：

1. 登录到 [Microsoft Entra 管理中心](https://entra.microsoft.com/)。
2. 转到**Microsoft Entra ID**>**企业应用程序**>**所有应用程序**。
3. 选择应用程序，然后选择 **“属性**”。
4. 查看 **所需的工作分配？**。

然后使用与预期访问策略匹配的解决方法。

### 保持“分配”为必填项

如果只有选定的用户和组才应具有访问权限：

1. 在企业应用程序中，选择 **“用户和组**”。
2. 选择“添加用户/组”。
3. 选择要分配的用户或组。
4. 选择应用程序角色。 如果应用程序未公开命名角色，请选择“ **默认访问**”。
5. 选择**分配**。

有关详细信息，请参阅[向应用程序分配用户和组](/zh-cn/entra/identity/enterprise-apps/assign-user-or-group-access-portal)。

### 不需要分配

如果租户中的所有其他授权用户都应能够访问应用程序：

Important

将 **“需要分配吗?”** 设置为 **“否”** 会扩大令牌的适用范围，使未分配的用户和应用程序也包含在内。 仅当它与组织的预期访问策略匹配时，才进行此更改。

1. 在企业应用程序的 **“属性** ”页上，将 **“需要分配”** 设置为 **“否**”。
2. 选择**“保存”**。

此项更改移除了赋值检查。 其他访问控制（如条件访问策略和特定于应用程序的授权）仍适用。

### 使用受影响的身份进行验证

与收到该错误的用户一起测试此项更改。 请勿使用全局管理员来验证分配，因为分配要求不适用于该角色。
