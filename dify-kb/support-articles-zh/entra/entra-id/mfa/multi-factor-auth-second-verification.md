# 未提示为 Azure 多重身份验证启用的某些用户提供第二种验证方法

本文介绍在登录时未提示启用 Azure 多重身份验证的用户出现第二个验证因素的情况。

*原始产品版本：*Microsoft Entra ID、云服务（Web 角色/辅助角色），Microsoft Intune  
*原始 KB 数：* 3124671

## 现象

设置条件访问策略以便强制实施 Azure 多重身份验证时，不会提示某些用户通过第二种验证方法验证其标识。 此问题可能发生在以下两种情况下。

**方案 1**：多重身份验证在记住的设备上暂停：

在此方案中，管理员为多重身份验证设置受信任的网络，并允许 **用户通过导致设备记住** 选项来暂停多重身份验证。

**方案 2**：用户是异常组的成员：

在此方案中，用户是应用的异常组的成员。 当管理员为应用设置多重身份验证访问策略时，管理员可以选择 **“例外** ”框，将组设置为例外。 即使配置了这些方案中的设置，你仍希望用户收到第二个验证方法的提示，因为你应用的条件访问策略。

## 解决方法

**对于方案 1**：

1. 确认 **是否已启用“允许用户暂停多重身份验证** ”选项。
2. 如果启用此选项，请让用户尝试以下一项或多项操作：
   - 删除浏览器 Cookie。
   - 使用其他浏览器。
   - 使用 InPrivate 浏览会话。

**对于方案 2**：

- 从异常组中删除用户。
- 从异常组列表中删除该组。

## 详细信息

**对于方案 1**：

此选项使通过多重身份验证成功进行身份验证的用户可以避免未来 1-60 天的多重身份验证提示，具体取决于设备必须重新进行身份验证**设置前几天配置**的值。

即使应用设置为**“要求多重身份验证”、“在工作时**需要多重身份验证”或**“阻止在工作**时阻止访问”，并且用户的设备不在受信任的网络上，也是如此。

**对于方案 2**：

对于属于异常组成员的用户，将重写用户帐户上的多重身份验证要求。
