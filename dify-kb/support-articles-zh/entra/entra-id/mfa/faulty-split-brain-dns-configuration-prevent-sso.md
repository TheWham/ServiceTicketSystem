# 错误的拆分脑 DNS 配置可以防止无缝 SSO 登录体验

本文介绍使用启用了单一登录（SSO）的用户 ID 登录到 Office 365 服务时，Active Directory 联合身份验证服务（AD FS）的行为不符合预期的条件。

*原始产品版本：* 云服务（Web 角色/辅助角色）、Microsoft Entra ID、Microsoft Intune、Azure 备份、Office 365 标识管理  
*原始 KB 数：* 2715326

## 现象

使用启用了单一登录（SSO）的用户 ID 登录到 Microsoft 云服务（如 Office 365、Microsoft Azure 或 Microsoft Intune）时，与 Active Directory 联合身份验证服务（AD FS） 的连接不会按预期方式运行。 连接失败并出现以下结果之一：

- 从本地网络内部登录的计算机连接到 AD FS 代理 IP 地址，并显示基于表单的身份验证提示。 但是，需要集成 Windows 身份验证体验。
- 由于防火墙设置，从本地网络内部登录，然后尝试连接到 AD FS 代理服务的计算机被拒绝。

## 原因

这些症状可能是由于 DNS 服务的内部和外部名称解析需要错误的拆分脑 DNS 配置引起的。 以下原因之一最有可能：

- 未为 AD FS 服务所在的域设置拆分脑内部 DNS 解析。
- AD FS 服务名称解析未在本地环境的拆分脑内部 DNS 解析中设置。

## 解决方法

若要解决此问题，请执行以下步骤：

### 步骤 1：在内部 DNS 中建立拆分脑 DNS 区域

为此，请在本地 DNS 服务器上执行以下步骤：

1. 打开 DNS 管理控制台。 为此，请打开 **管理工具**，然后双击 **DNS**。
2. 在左侧导航窗格中，展开 **DNS**，展开服务器名称，然后选择 **“转发查找区域**”。
3. 如果没有为托管 AD FS 服务终结点的 DNS 区域显示条目，请创建区域。 为此，请右键单击“ **向前查找区域**”，然后选择“ **新建区域**”。
4. 完成向导。 执行此操作时，请选择“ **主区域**”，然后为 AD FS 服务器的 DNS 域命名区域。

   警告

   完成此步骤实际上会阻止本地计算机通过使用解析域公共请求的 DNS 服务器将服务器名称解析为公共 IP 地址。 任何必须由本地客户端使用的 Extranet 服务终结点都必须在拆分脑 DNS 配置中创建 A 记录才能启用连接。

### 步骤 2：在拆分脑 DNS 域中播发 AD FS 服务终结点

在前面打开的 DNS 管理控制台中，执行以下步骤：

1. 浏览到 AD FS 服务器的域，然后选择 DNS 区域。
2. 右键单击域名，然后选择“新建主机”**（A 或 AAAA）。**
3. 输入以下值：
   - 名称：AD FS 服务名称
   - IP 地址：AD FS 联合身份验证服务场的本地专用 IP 地址。

### 步骤 3：清除服务器和客户端上的 DNS 缓存以测试解决方案

1. 在前面打开的 DNS 管理控制台中，右键单击服务器名称，然后选择“ **清除缓存**”。
2. 在客户端计算机上，依次选择“**开始**”、“**所有程序**”、“附件**”、“**命令提示符**”**，然后选择“**以管理员**身份运行”。
3. 键入以下命令，然后按 Enter：

   ```
   Ipconfig /flushdns
   ```

重新测试 SSO 登录，确认此问题已解决。

## 详细信息

拆分脑 DNS 是一种常见配置，用于确保本地客户端计算机将服务器名称解析为内部 IP 地址，即使公共 DNS 解析将相同的服务名称解析为不同的公共 IP 地址。 为本地服务设置 AD FS 时，需要此配置来确保对 AD FS 服务的本地客户端计算机的身份验证体验处理方式与 AD FS 代理服务所服务的外部客户端计算机不同（由 AD FS 联合身份验证服务场处理）。

如果没有此配置，所有 AD FS 客户端都将在连接到 AD FS 服务时使用相同的 IP 地址提供服务，无论是从本地网络连接还是从 Internet 位置远程访问。 这会限制本地 Active Directory 身份验证的客户端的无缝身份验证体验，因为向 Internet 公开 AD FS 服务的 AD FS 代理服务不希望访问客户端在没有提示的情况下提供集成的 Windows 身份验证响应（因为远程计算机未向 Active Directory 进行身份验证）。

若要克服此限制，最好通过在本地 DNS 中创建同名域来替代提供给本地客户端的默认名称解析。 由于 DNS 分布式体系结构返回对正向查找查询找到的第一个响应，因此这会有效地屏蔽针对所有本地客户端计算机请求的域的公共 DNS 域播发，因为它们的请求首先由本地 DNS 服务器处理。
