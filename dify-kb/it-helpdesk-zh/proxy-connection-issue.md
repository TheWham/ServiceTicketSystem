# 代理（Proxy）连接不上排查指南

## 问题现象

浏览器提示"无法连接到代理服务器 / ERR_PROXY_CONNECTION_FAILED"；需要代理才能访问的系统打不开；代理客户端（VPN 客户端、Clash 类工具、公司上网代理）显示已连接但实际打不开网页。

## 先分清是哪种"代理"

| 类型 | 典型场景 | 配置位置 |
|---|---|---|
| 公司统一上网代理（PAC/固定地址） | 内网办公机访问互联网 | Windows「设置 → 网络和 Internet → 代理」 |
| 浏览器内代理插件 | 仅某个浏览器访问不了 | 浏览器扩展管理页 |
| 第三方代理/VPN 客户端 | 客户端显示连接失败 | 客户端软件本身 |

分不清时，先按本指南顺序排查；公司上网代理问题优先联系 IT 确认是否需要申请开通。

## 步骤一：检查 Windows 系统代理设置

1. 打开「设置 → 网络和 Internet → 代理」。
2. 确认状态与你的预期一致：
   - **应该用公司代理**：「使用设置脚本」为开，脚本地址为公司下发的 PAC 地址；或「使用代理服务器」为开，地址/端口与 IT 提供的一致。
   - **不应该用代理**（家用网络/已离职设备）：三项开关全部关闭，否则浏览器会一直尝试连一个不存在的服务器。
3. 第三方代理软件退出后未还原系统代理是常见原因——先全关再逐项恢复。

## 步骤二：代理服务器本身是否可达

命令提示符（`cmd`）执行（把地址端口换成实际的）：

```
ping 代理服务器地址
curl -x http://代理地址:端口 https://www.bing.com -I
```

- `ping` 不通 → 网络层问题，转查 [网络连接不上](network-no-internet-dns.md)。
- `curl` 返回 407 Proxy Authentication Required → 需要认证，确认账号密码或未在代理白名单中，联系 IT。
- `curl` 正常但浏览器不行 → 问题在浏览器，继续步骤三。

## 步骤三：浏览器侧排查

1. 换一个浏览器对比（Edge / Chrome / Firefox）。
2. 仅某个浏览器不行：禁用全部扩展（尤其代理类插件）后重试；清除浏览器缓存和 Cookie。
3. Chrome/Edge 也可以带参数启动测试：`chrome.exe --no-proxy-server`，绕过代理后正常则说明是代理配置问题而非网络问题。

## 步骤四：第三方代理客户端排查

1. 完全退出客户端（右下角托盘也退出）再重启，必要时重启电脑。
2. 检查客户端的"系统代理/TUN 模式"开关，尝试切换模式。
3. 确认订阅/配置未过期，服务器节点更换一个试试。
4. 检查本机防火墙或安全软件是否拦截了客户端，临时关闭测试后记得恢复。
5. 与其他代理/ VPN 软件同时运行会互相打架，一次只开一个。

## 步骤五：重置网络栈（仍不行时）

以管理员身份运行 `cmd`，依次执行，完成后重启电脑：

```
netsh winsock reset
netsh int ip reset
ipconfig /flushdns
```

## 常见报错对照

| 报错 | 含义 | 方向 |
|---|---|---|
| ERR_PROXY_CONNECTION_FAILED | 系统代理地址不可达 | 步骤一、二 |
| ERR_TUNNEL_CONNECTION_FAILED | HTTPS 经由代理建连失败，多为代理拦截/证书问题 | 联系 IT 或换节点 |
| 407 Proxy Authentication Required | 代理要求认证 | 找 IT 确认账号/白名单 |
| 仅个别网站打不开，其余正常 | 代理或出口对该站点限制 | 联系 IT，不走自助 |

## 什么时候联系 IT

- 公司下发代理失效且你无权修改；
- `curl` 测试代理返回 407 / 超时，需要开权限或加白名单；
- 同一时间多台电脑都上不了网 → 大概率是代理服务器或出口故障，直接报障。

## 转人工时请提供

- 完整报错截图（含地址栏网址可打码敏感域名，但保留错误代码）；
- 代理类型（公司上网代理 / 第三方客户端）及配置截图；
- 上述 `ping`、`curl` 结果。
