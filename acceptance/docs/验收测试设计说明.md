## 1. 概述

本模块是企业 IT 服务工单系统验收评测体系中 **第 1 条执行轨道——提单链路自动化回放**
（V2 §4.1-1）的实现，覆盖指标 **M-01~M-09**（权重合计 48%）与样本 **TC-01~TC-10**。
V2 全量 16 项指标中的 M-10~M-13 由 ticket-service / consultation-service 服务端集成测试覆盖，
M-14~M-16 由 `evals/golden_datasets` 金标数据集回放覆盖，均不在本模块职责内，
但回放报告按 16 项全量口径列示并标明回填责任方。

模块交付物四件套：

```
acceptance/
├── .cursorrules                 # 受控代码生成约束（8 章铁律）
├── src/ticket_p0/               # SPEC → 代码 的实现（仅标准库）
├── tests/                       # 质量负责人测试集（27 项 pytest 用例）
└── scripts/run.py               # 验收回放脚本（协议格式的产出 + §4.2 判定 + CI 退出码）
```

## 2. 测试生成机制（受控代码生成流水线）

本模块遵循 **「测试先行、受控生成」** 的流水线，证据链可追溯：

1. **输入**：《验收评测协议书 V2》（§3.1 样本集 / §2.1 指标总览 / §4.2 判定）与《技术 SPEC 规格书 V1.1》；
2. **生成约束**：`.cursorrules` 将两份文档转译为 8 章"铁律"——只允许的错误码清单
   （0/40000/40100/40300/40400/40401/40900/40901/500）、七字段校验矩阵、13 条状态机合法边、
   幂等与并发规则、附件魔数嗅探安全红线、禁止事项。AI 代码生成必须逐条遵守，违反任一条即返工；
3. **测试先行**：质量负责人角色先编写 `tests/test_service.py`，每条用例均可反查到具体协议条款
   （见 `README.md` 的"文档 → 代码 → 测试"对照表），随后实现 `src/ticket_p0/` 至全绿；
4. **回放验收**：`scripts/run.py` 逐条回放 10 个样本、实测 9 项指标，自动生成
   《验收评测执行记录-实测.md》并输出 §4.2 综合判定与进程退出码。

### V2 相对初版的三处实质变更（已落地）

## 3. 运行方式

```bash
cd acceptance
python -m pytest -v      # 27 项确定性断言（约 0.2s，大屏展示目标 100% Passed）
python scripts/run.py    # 回放生成《验收评测执行记录-实测.md》；判定不通过时退出码 = 1（可接 CI 门禁）
```

### 确定性保障（结果可重复、可签字）

- **固定时钟**：`tests/conftest.py` 以 `FixedClock(2026-09-21 12:00)` 冻结时间轴，
  3 秒幂等窗、2 小时超时告警、60 秒通知幂等窗均由 `clock.advance()` 精确推进，不受真实时间影响；
- **隔离评测库**：每个用例/`new_service()` 使用全新 `:memory:` SQLite，种入 3 个角色账号
  （员工 E1001 / 工程师 E2001 / 主管 E9001）与 4 条 CMDB 资产，用例间零污染、不触生产库；
- **样本精确核验**：TC-08/09 边界值字符数（title=50/51、desc=500/501、资产字母段 2/5 位）
  经脚本精确构造并断言长度；
- **附件向量**：合法 JPEG（FFD8FF）/ PNG（89504E47）/ 可执行文件（MZ 头）字节序列内置为常量，
  专验魔数嗅探。

## 4. 用例详解（27 项）

### 4.1 正向样本 TC-01 ~ TC-05（5 项）

五分类各一条合法提单，断言全部放行落库。其中 **TC-01（硬件·高优·全字段）** 最重，一条样本同时承载：

- **M-03 字段提取**：落库 7 字段与提交值逐字段一致（description 不被截断、attachment_urls 为 JSON List）；
- **M-09 CMDB 联动**：资产命中回显型号与责任人；
- **M-05 建单合法性**：ticket_id 符合 `TK+yyyyMMdd+4位序号`、初始状态合法、creator_id=当前用户；
- **通知事件**：SUBMIT_SUCCESS 落库（LOG 通道 / SUCCESS）；
- **流转日志**：from=NULL → CREATED。

TC-02~05 分别覆盖：软件类无资产（assetId 选填）、网络类无附件（附件选填）、
账号类最简四字段、其他类低优 + 资产 + 1 附件。

### 4.2 必填拦截 TC-06 / TC-07（2 项）

- **TC-06**：空标题 → 40000 拦截，错误字段集合含 `title`，不落库；
- **TC-07（V2 变更样本）**：描述为空 → 拦截，提示 **「请填写问题描述」**，不落库。

### 4.3 边界值 TC-08 / TC-09（2 项）

- **TC-08 临界合法**：title=50（上限）、desc=10 字（合法，V2 起无下限）、资产字母段 2 位（正则下界）→ 全部放行；
- **TC-09 临界非法**：title=51 / desc=501 / 资产字母段 5 位 / 期望时间在过去 →
  **四字段同时越界时逐字段收集、一次性返回**（禁止遇第一个错就中断），且不落库。

### 4.4 注入安全 TC-10（1 项，V2 §4.2 零容忍样本）

一条用例验证四类攻击向量：① XSS——标题含尖括号直接拒绝；② SQL 注入——
description 中的 DROP TABLE 语句作为普通文本参数化落库，表完好、内容原样；③ 路径穿越——
`../../etc/passwd` 被资产正则拦截；④ 伪造附件——.exe 伪装 .jpg，**魔数嗅探**拒绝（不信任扩展名）。

### 4.5 指标实测 M-01 / M-05 ~ M-09（6 项）

| 用例 | 内容 | V2 门禁 |
| :--- | :--- | :--- |
| test_m01 | 10 条样本回放（真阳性非法拦截 + 真阴性合法放行），误判分级「漏拦×2 / 误拦×1」 | 100% |
| test_m05 | 5 条校验通过样本全部落库 + ticket_id 合法 + creator_id=当前登录用户（生产 SLO ≥99.95% 由 APM 度量） | 100% |
| test_m06 | 3 秒窗内同用户同标题连点 5 次仅落库 1 条、拦截码 **40901**、窗口外放行（零容忍项） | 100% |
| test_m07 | 推荐接口超时异常 → 静默降级返回空、不阻塞提单（Mock 回放；AI 熔断/ES 补偿场景属智能链路） | 100% |
| test_m08 | 附件四维校验：格式白名单 / 单张 ≤5MB / ≤3 张 / 魔数与扩展名一致（零容忍项） | 100% |
| test_m09 | 资产正则 + CMDB 联动：查无 → 40401，查中 → 回显型号与责任人 | 100% |

### 4.6 状态机与守卫（5 项）

- **全链路合法流转**：SUBMIT → ACCEPT → 请求补充 → 补充 → 转外部 → 恢复 → 提交方案 → 验收驳回 →
  返工 → 再提交 → 验收通过 → 关闭，共 11 步；每步断言状态、assignee、reject_count，
  并将 12 条流转日志动作、10 条通知事件 **逐一比对期望值**；
- **非法流转**：不存在的状态机边（如 CREATED 直接提交方案）→ 40900，状态不变、无日志写入；
- **角色守卫**：员工不能接单（40300），SUPERVISOR 对角色守卫放行；
- **本人守卫**：补充/验收/关闭仅提单本人，SUPERVISOR 也不放行 creator_only；
- **乐观锁**：expected_version 过期 → 40900「工单已被他人操作」；终态不可逆、CREATED 可本人撤单；
  remark 必填（请求补充/驳回必须填说明）。

### 4.7 超时降级 T2 / T3（2 项）

- **T2**：处理中超 2 小时未更新 → 仅落 TIMEOUT_ALERT 通知主管，**状态绝不被隐式修改/自动销毁**；
  60 秒幂等窗内重复扫描不轰炸，窗口外重新告警；
- **T3**：待外部滞留超 24 小时 → 同时催办提单人与处理人，状态保持不变。

### 4.8 兜底能力（2 项）

- **草稿**：一人一份、覆盖保存、提单成功自动清除；
- **发号**：ticket_id 当日原子递增（seq 表 ON CONFLICT 自增），跨提交不串号。

## 5. 验收回放脚本（scripts/run.py）工作机制

1. **逐条回放 TC-01~TC-10**：每条样本在全新 `:memory:` 服务上执行，记录实际校验结果、
   ticket_id、耗时，判定"符合预期"；TC-01 同时计算 M-03 七字段 **加权** 比对得分
   （title 0.2 / category 0.2 / priority 0.15 / description 0.25 / asset_id 0.1 /
   attachment_urls 0.05 / expected_finish_time 0.05，V2 §2.2.3）；
2. **实测 M-01~M-09**：M-04 以 20 次提单进程内采样计算 P95/P99（仅覆盖 V2 §2.2.4 的 M-04b 子项，
   04a/04c/04d 以前端埋点与 AI 链路实测为准）；M-06 连点 5 次断言 40901；
   M-07 注入超时 Recommender 验证降级；M-08/M-09 多断言汇总；
3. **生成报告**：执行记录表 + **V2 全量 16 项指标汇总表**（M-01~09 实测、M-10~16 标注阈值与回填责任方）
   + **§4.2 综合判定**：逐项判定全部达 100% 门禁 **且** 回放范围内零容忍项（M-06 / M-08 / TC-10）
   无违反 → 通过；加权得分 48/48 仅用于质量分级，不替代逐项阈值判定；
4. **CI 集成**：判定「不通过」时进程退出码为 1，可直接作为流水线质量门禁。
