# 企业级 Agent 开发全流程

> 核心链路：**需求定义 → 能力拆解 → 架构设计 → 提示词/工具开发 → 编排 → 评测 → 部署运维 → 迭代** 区分：玩具Agent（单轮、简单工具调用）vs 企业Agent（长会话、权限隔离、审计、可回滚、可监控、对接内部系统）

## 一、需求与场景定义

先不写代码，先回答4个问题

1. **目标角色**：这个Agent是谁？（采购助理/数据分析师/工单客服/合同初审）
2. **边界范围**：什么能做、绝对不能做（禁止直接改数据库、禁止对外泄露客户敏感信息）
3. **用户是谁**：内部员工 / 客户 / 运维；决定权限、交互入口（企微、内部平台、API）
4. **成功指标**（可量化，不是“智能好用”）
   - 业务指标：人工替代率、工单一次解决率、审核通过率
   - Agent指标：任务完成率、工具调用错误率、召回率、幻觉率、平均耗时

✅ 输出物：BRD、角色SOP、拒绝话术清单、风险清单（敏感数据、越权操作）

> 示例场景：供应链询报价Agent
> ✅ 可以：查历史报价、拉供应商清单、生成询价单草稿
> ❌ 禁止：直接确认订单、修改合同价格

## 二、能力拆解 & 工具规划（Agent核心：大模型是大脑，工具是手脚）

Agent本身不会“真的知道企业数据”，**所有确定性业务操作都交给工具**，大模型只负责：理解意图、选工具、组装参数、汇总结果。

### 工具分类（企业常用）

1. **检索类工具**：RAG知识库（合同、制度、产品手册）、向量库（Milvus/Chroma）
2. **系统对接工具**：SAP/MES/CRM/OA接口、数据库查询API、工单系统、邮件接口
3. **计算/代码工具**：Python沙盒（统计、报表、复杂公式，**必须沙盒隔离，禁止任意执行代码**）
4. **通用工具**：联网搜索、文件解析（PDF/Excel/Word）、图片OCR
5. **人工兜底工具**：转人工审批、人工复核节点（企业Agent必备！）

⚠️ 原则：**能做成工具的，不要让大模型猜**。比如查库存，直接调用库存API，不要让模型从文档里推断库存。

✅ 输出物：工具清单 + 每个工具的入参、出参、权限、异常返回定义（OpenAPI格式）

## 三、架构选型（两种主流路线）

### 路线A：单Agent（适合单一业务场景，合同审核、数据查询）

经典组件：

- 入口层：前端/企微/API网关
- 会话记忆层：短期记忆（当前对话）、长期记忆（用户档案、历史任务）
- 规划器（Planner）：LangGraph / AutoGen 做任务拆解，把大任务拆成多步子任务
- 工具调度器：判断调用哪个工具、填参数
- 反思器（Reflector）：拿到结果后校验，失败重试、换工具、或者转人工
- 安全网关：输入过滤、输出脱敏、权限校验
- 可观测：Langfuse / OpenTelemetry 记录每一步trace、token、耗时、幻觉标记

### 路线B：多Agent协同（复杂业务，比如采购全流程：需求Agent→供应商Agent→合同Agent）

- 主管Agent（调度）：分发任务、汇总结果、仲裁冲突
- 专业子Agent：各司其职，互相不越界
- 消息总线：Agent之间通信，带消息日志、审计

> 选型口诀：简单任务单Agent；跨多个独立业务、需要不同专业能力 → 多Agent
> 框架选择：LangGraph（国内生产最稳，可控、支持循环、分支、人工节点）、AutoGen、LlamaIndex Agent

## 四、Prompt、记忆、规划开发

1. **系统提示词（System Prompt）** 固定角色、SOP、约束、格式、禁止事项；企业场景重点加：**脱敏要求、拒绝策略、什么时候转人工**
2. **记忆管理（企业Agent重中之重）**
   - 短时记忆：当前任务上下文（放在对话窗口，有上限，防止上下文溢出）
   - 长时记忆：向量库存储历史任务、用户偏好；**必须区分：业务数据 ≠ 对话记忆**
   - 记忆压缩：长对话自动摘要，防止token爆炸
3. **规划模式两种**
   - 顺序规划：先写计划，再一步步执行（适合长任务，比如审计）
   - 反应式ReAct：思考→调用工具→观察结果→再思考（简单查询场景）

## 五、安全、权限、数据隔离（企业和Demo最大区别）

这一块是能不能上线的门槛

1. **权限鉴权**：每个工具调用携带用户身份，工具后端做二次鉴权。A员工只能查自己部门工单，Agent不能越权
2. **输入防护**：Prompt注入拦截、恶意指令检测
3. **输出防护**：敏感信息脱敏（手机号、身份证、报价、成本自动掩码）
4. **幻觉控制**：所有结论引用来源ID；不确定时直接返回“无法确认，转人工”，禁止编造数据
5. **审计日志**：每一次提问、每一次工具调用、返回结果、操作者、时间全部落库，可追溯、可导出审计报告

## 六、评测体系（不是简单聊两句看看好不好用）

分三层评测：

1. **单元评测：工具层**：每个工具入参异常、超时、返回空的时候能不能正确处理
2. **Agent链路评测（核心）**
   - 任务完成率：能不能走完完整流程拿到正确结果
   - 幻觉率、错误工具调用率、误召回率
   - 拒绝准确率：不该做的事情会不会拒绝
3. **业务灰度评测**：真实员工小批量试用，收集负样本（失败case）

✅ 输出：评测数据集（黄金测试集），每次版本迭代回归测试，防止改Prompt后能力退化

## 七、部署上线 & 可观测（LLMOps）

1. 部署形态：API服务，对接内部门户、企业微信、钉钉；**不要直接把大模型暴露给用户**
2. 资源隔离：模型推理、Agent编排服务、向量库、业务接口分开部署
3. 监控（Langfuse重点在这里）
   - 指标：调用量、失败率、token消耗、耗时、费用
   - Trace：每一步：思考内容、工具入参、工具返回、模型输出，出问题可以回放整个流程
   - 告警：连续调用失败、大量幻觉、越权尝试直接告警给管理员
4. 灰度上线：先给少数种子用户，收集case，再放量

## 八、运维迭代闭环（长期运营）

Agent上线不是终点，是持续迭代：

1. 收集失败Case：哪些任务卡壳、乱调用工具、幻觉
2. 分类优化：
   - 缺知识 → 补充RAG文档
   - 工具参数经常填错 → 优化提示词 / 增加参数校验
   - 规划逻辑错 → 修改LangGraph流程图、增加分支判断（人工复核节点）
3. 定期重跑评测集，版本管理（Prompt版本、Agent流程版本）
