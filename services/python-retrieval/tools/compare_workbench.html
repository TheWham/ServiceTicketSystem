1 三元组提取的完整工业级流水线 (5 重安全防漂移防线)

① 元数据治理注入

解析 Markdown Frontmatter 中的 replaces、entities，直接注入确定性治理三元组（废止并替代、生效状态、依赖分类），零幻觉。

② 实体候选池约束

将卡片中标准名词注入 LLM Prompt 模具，强制大模型只能以候选池名词作为头尾实体，杜绝生成天马行空的自造词。

③ Quote Grounding 逐字比对

每条三元组必须携带 evidence_quote，程序在卡片原文中执行逐字子串校验，只要原文没有该句直接拦截丢弃。

④ 别名消歧与内存建图

通过 canonicalize_entity 将“AD域/域控”等口语归一化为标准节点，批量写入 NetworkX 内存多重图，耗时仅 0.05 秒。

2 传统向量检索 vs Graph 链路检索结果的根本区别

🔴 纯向量检索产出：孤立切片集合 (Unconnected Chunks)

输入 Query 后计算 Embedding 向量余弦距离，召回 3~5 个 512 字符的小切片。切片之间互不连通、没有因果关系。面对“VPN 报错 691”，向量库仅因字面相似召回了 VPN 客户端重启与网络排查，而深藏在另一张《账号锁定处置》卡片中的“手机邮箱旧密码轮询锁定 AD 域”切片由于字面不包含 VPN，在相似度排序中彻底沉底无法被召回，形成信息孤岛。

🟢 Graph 双轨融合产出：因果拓扑网 + 完整父卡正文

输入 Query 后识别出种子实体，在 Neo4j 图数据库中执行原生 Cypher 2-Hop 变长路径遍历与拓扑匹配，抽取出显式因果链路（VPN错误691 ──(根因)──> AD域锁定 ──(根因)──> 手机邮箱旧密码轮询）；同时将指向已废止旧规的节点在 Cypher 索引层执行剪枝过滤；接着顺藤摸瓜找到涉及的核心卡片 ID，批量从 MySQL Docstore 中取出完整父卡。

3 LLM 如何将拓扑事实与正文内容融合整合？(骨架 + 血肉架构)

推理器构造了双轨融合 Prompt，将图谱事实与知识库正文划分了严谨的责任分工与优先级：

【系统客观拓扑事实（最高优先级刚性骨架，不可违背）】 1. VPN错误691 ──(诱发根因)──> AD域账号锁定 2. 移动端邮件客户端旧密码轮询 ──(诱发根因)──> AD域账号锁定 3. 检查客户端旧密码 ──(前置排查动作)──> AD域账号锁定 4. Active Directory用户和计算机 ──(处置动作)──> AD域账号锁定 5. ITKB-VPN-001 ──(废止并替代)──> ITKB-LEG-VPN-001 【关联知识库参考正文（提供细节血肉与操作命令）】 ### 【卡片 ITKB-VPN-001 参考正文】包含 VPN 客户端配置、预共享密钥检查... ### 【卡片 ITKB-ACC-001 参考正文】包含手机邮箱退出登录步骤、事件ID 4740 安全日志排查... 【用户问题】在家连不上公司VPN，提示691，手机邮箱也提示凭据失效...
第一步：拓扑定锚 (定因果)

LLM 首先读取拓扑事实，确立严格因果链条（手机邮箱轮询 -> AD账号锁定 -> VPN 691 认证失败），绝不把原因误判为本地路由器故障。

第二步：版本仲裁 (防旧规)

发现拓扑中包含废止与替代关系，强制 LLM 只采信现行有效版本，彻底屏蔽已废止卡片中的失效条款。

第三步：正文填充 (补细节)

沿着因果骨架，从 MySQL Docstore 父卡正文中摘录“事件ID 4740”、“先退手机邮箱登录”等操作细节，组织成带【证据链推导】与【处置步骤】的严密终答。
