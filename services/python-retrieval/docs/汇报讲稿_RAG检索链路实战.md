## 第一幕：100% 的幻觉——评测口径饱和

### 现象
四轨 Hit Rate@3 全部 21/21。加 rerank 的精链路和裸 BM25 打平，精排的价值无法证明。

### 根因（四个叠加）
1. **题库与语料同源**：7 道题是从 Wiki 卡片反着写的，query 里直接带答案词面（"806""550""sfc /scannow"）——自证题；
2. **判定口径太松**：旧口径是"期望词作为子串出现在 Top-3 拼接文本里"，且命中子块后回溯**整卡全文**再比对；
3. **期望词混入高频通用词**：实测语料——"时间"出现在 8/35 张卡、"地址"9/35、"停止"6/35。**召回错卡也能误命中**；
4. **指标不含排序质量**：正确卡排第 1 还是第 3 得分相同。

### 解法（代码：`rag_pipeline/pipelines/evaluation.py` 的 `_track_metrics`）
```python
ids = [d.metadata.get("wiki_id") for d in parents]          # 回溯父块的卡片 id 序列
rank = (ids.index(target_id) + 1) if target_id in ids else None   # 卡级名次
if target_id:
    tgt_text = next(d.page_content for d in parents
                    if d.metadata.get("wiki_id") == target_id)    # 只取目标卡正文
    hits = sum(1 for f in expected if f in tgt_text)               # 事实只在目标卡内计数
```
三件事：
- **卡级金标准**：每题显式标注 `target_id`，看目标卡进没进 Top-3、排第几（Recall@3 + MRR）；
- **事实覆盖限目标卡**：目标卡没召回，事实一律记 0——高频词误命中被物理消灭；
- **题库扩容**：+3 道同义改写题（query 刻意不含卡片词面）+2 道库外负样本（考拒答能力）。

### 结果
| 链路 | 旧口径 | 新口径 Recall@3 / MRR |
|---|---|---|
| A 纯 Dense | 100% | 9/10 · **0.90** |
| B 纯 BM25 | 100% | 9/10 · 0.70 |
| C RRF | 100% | 9/10 · 0.85 |
| D 全链路 | 100% | 9/10 · 0.83 |

"100% 消失了，**故事出现了**：BM25 在改写题上脱靶、全链路被精排拖后腿——这些才是能指导工程的信号。"

## 第二幕：切片的碎与噪——170 个子块里的 38 个垃圾

### 现象（翻材料：`day12_output/chunk_preview.md` 旧版）
- 每卡第一个子块 c0 只有 110~170 字符（标题+检索增强词），不承载任何排查步骤；
- 文末 `> 🔗 溯源：…` 模板行把最后一节顶出一个 200 字的碎块 c5；
- 每个子块重复注入 ~80 字符全局实体词，**稀释步骤块的向量**（实测强匹配 query 相似度 0.639→0.588）。

### 解法（代码：`rag_pipeline/chunking/parent_child.py`）
```python
child_src = re.sub(r"\n-{3,}\s*\n>\s*🔗\s*溯源：[^\n]*\s*$", "", body)   # ① 溯源尾剔除（仅子块，父块保留）
for ln in child_src.splitlines(keepends=True):
    if ln.startswith("## "):                                            # ② H2 语义边界分节
        sections.append((cur_h2, cur_lines)); ...
if cfg.merge_preamble and len(sections) > 1 and not sections[0][0]:     # ③ 前言并入首节
    sections = [(sections[1][0], sections[0][1] + sections[1][1])] + sections[2:]
hdr = header + (boost if idx == 0 else "")                              # ④ 检索增强词只挂每卡首块
```
设计取舍一句话：**H2 小节定边界（事实链不拦腰斩）、行累加控大小（不切断行）、差异化注入两全其美**——BM25 靠首块词表命中整卡，Dense 靠干净步骤块保持向量纯度。

### 结果
- 子块 170 → **132**；BM25 MRR 0.70 → **0.78**（HC-07 端口题从第 3 位升到第 1 位）；
- Dense 不受损（0.90 持平）——稀释消除与词表保留正好抵消。

## 第三幕：精排误杀案——HC-10 与"稳定的错误"

### 现象
HC-10（"汇总列数字不跟着变"→OFF-004 公式卡）：Dense 第 1、RRF 第 2，**全链路却把目标卡挤出 Top-3**。Rerank 把正确候选打到低名次。

### 调查（翻材料：`day13_output/rerank稳定性压测报告_hc10.html`）
写了压测脚本 `test_rerank_stability.py`：同一输入连打 20 次。
```
ITKB-OFF-001(错卡)   0.295  ← 20/20 次第 1
ITKB-OFF-004(正确卡) 0.232  ← 20/20 次第 3     std = 0.000
```
**结论颠覆直觉**：不是"分数漂移"（同输入零漂移），是**系统性排序偏差**——模型对零词面重叠的同义改写题稳定地判错。重跑/调参无意义。

### 解法：三层防线（代码：`rag_pipeline/retrieval/hybrid.py`）
```python
# 层2：按秩加权融合——精排只拿 0.4 的票，召回侧 RRF 拿 0.6 托底
fused_score = (rrf_weight / (fuse_k + rrf_rank)) + (rerank_weight / (fuse_k + rr_rank))

# 层3：Top-1/2 双路共振保护——两路独立侦探意见一致时，法官反对票无效
protected_parents = _top_parent_ids(bm25_res) & _top_parent_ids(dense_res)   # 两路前2名父块交集
for pid in protected_parents - final_parents:
    best = max((d for d in scored_docs if _pid(d) == pid), key=...)          # 强制换回 Top-K
    rescued["protected"] = True
```
加上层1（第二幕的输入侧去噪），HC-10 从"挤出 Top-3"回到**第 2 位**。

### 结果
全链路 Recall@3 9/10 → **10/10**，MRR 0.83 → 0.85。详细召回报告里被保护换回的卡片带 🛡 标记（本轮未触发=前两层已够用，保险丝备而不用）。

## 第四幕：尺子是坏的——rerank 绝对分为什么不能信

### 现象（现场可复现的探针实验）
| 查询（对同一篇正确文档） | 分数 |
|---|---|
| **卡片自己的标题原句（完美匹配）** | **0.1534 ← 全场最低** |
| 带关键词的强匹配问句 | 0.1971 |
| HC-10 同义改写 | 0.2374 |
| 完全无关的 WiFi 问题 | 0.1889 |

### 三个结论（汇报金句）
1. **绝对分不是置信度**：完美匹配拿最低分，说明它只是排序用的内部中间量；
2. **绝对分跨查询不可比**：mail550 题整体落在 0.32~0.42，hc10 题落在 0.17~0.30——换道题尺子就缩一截，**这正是按秩融合（用名次不用分数）的真正理由**，比"防漂移"更根本；
3. **拒答策略不能用绝对分阈值**："低于 0.3 拒答"会把完美匹配的 0.15 也拒掉——Day14 的置信度设计必须用查询内相对量（名次差、共振有无、与候选中位数的距离）。

## 第五幕：线上不稳定的实锤——/rerank 间歇性返回全 0

### 现象
验证报告格式时发现某题 Rerank 分 0.0000；单独探针确认该 query 下**所有候选都得 0 分**。重跑一轮，0 分漂移到了别的题——**端点级间歇故障**，与 query 无关。

### 系统的正确反应 + 如实呈现（代码：`hybrid.py` 退化检测）
```python
rerank_degraded = len({round(s, 6) for s in rerank_scores}) <= 1   # 全候选同分 = 精排无有效信号
```
全同分 → 名次全并列 → 精排贡献自动中和 → **优雅退化为纯 RRF 排序**；报告里该题标注"⚠️ Rerank 本轮无有效分，融合退化为纯 RRF 排序"（翻材料：详细召回报告 HC-04/HC-07 的 ⚠️ 注记）。

### 彩蛋结果
退化那轮全链路 MRR 反而 **0.85 → 0.90**——因为 RRF 本来排得对，是精排把它晃歪的。**精排"有分时不稳定、没分时靠退化兜底"，两端都证明召回侧托底是对的。**

## 第六幕：工程收口——从 demo 到可接入的包

### 问题
切片参数在 Day12/Day13 **两处硬编码**（`child_size=512` 各写一遍），改一处忘一处 = 静默错配；代码散落根目录。

### 解法
- 抽取 `rag_pipeline/` 包（ingestion/chunking/embedding/store/retrieval/evaluation/pipelines 七模块）；
- **配置中心 `configs/pipeline.yaml`**：切片规则、模型、检索参数、废止卡排除，单一真源；
- **同步机制**：Day12/13 共用 `build_chunker(config)` 工厂；建库时 manifest 落 `config_fingerprint`，Day13 加载前比对——**改 YAML 任何切片参数，旧库自动判失效重建**（现场可演示：child_size 512→384，Day13 立刻提示"切片配置已变更"并重建）。

**遗留（诚实交代，是下一阶段的入口）**：
1. 负样本 2/2 全误召回——系统没有"拒答"出口，Day14 做置信度策略（且已证明不能用绝对分阈值）；
2. reranker 对同义改写的系统性偏差是模型能力边界，工程已兜住，根治靠换模型（配置一行）；
3. 12 题 × 35 卡是冒烟级，接项目前需要黄金问题集自动化 + RAGAS 流水线。

**一句话总结**：我们没有让模型变聪明，我们让**系统不再依赖任何单点的聪明**——数据层降噪、指标层说真话、融合层对冲、配置层防错配。

## 附：预判提问与应答

- **Q：为什么还留按秩融合？不是说漂移不存在吗？**
  A：漂移只是它最初的动机；真正理由是异构分数不可比（BM25 0~30 vs 余弦 0~1 vs rerank 0.17~0.42）+ 绝对分跨查询不可比（第四幕探针）。名次是唯一的公共语言。
- **Q：Dense 单通道 MRR 最高，为什么不全用 Dense？**
  A：HC-01 的 `sfc /scannow` Dense 未召回——精确命令串是向量盲区，BM25 字面通道是另一条腿；且负样本上 Dense 同样全误召回。
- **Q：rerank 在这份小语料上是净负贡献（RRF 0.88 > 全链路 0.85），为什么还留？**
  A：小语料上确实如此，已如实记录；精排的价值主张在粗排候选上千的生产规模。`rerank_weight` 是 YAML 旋钮，一行可关做五轨对比。
- **Q：问题都解决了吗？**
  A：数据侧全清；模型能力边界（改写题偏差）用系统层兜住；拒答能力是已知缺口，有压测证据、有设计约束（不用绝对分阈值），排期 Day14。
